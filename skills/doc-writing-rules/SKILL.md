# doc-writing-rules

## 1. 목적

- 저장소 안 모든 Markdown 문서(README.md, docs/, HANDOFF.md, AGENTS.md, CLAUDE.md, skills/*/SKILL.md)의 작성 규칙을 한곳에 둔다.
- 다음 작업자는 이전 대화를 볼 수 없고 문서만 읽는다. 같은 머리말, 같은 제목 번호, 같은 용어를 써야 원본 위치를 빨리 찾고 문서끼리 충돌하지 않는다.
- 이 스킬은 문서 문체만 다룬다. 화면 문구(메시지, 버튼, 안내)의 문체와 머리말은 docs/04_디자인가이드.md 13.1 이 원본이고, 문구 자체는 docs/01_요구사항.md 5절이 원본이다.

## 2. 트리거 상황

- Markdown 문서를 새로 쓰거나 고칠 때. 작업 하나에서 문서를 바꿨으면 커밋 전에 바꾼 문서마다 실행한다.
- 단계 끝 보고 전(AGENTS.md 10절). 그 단계에서 바뀐 문서 전체를 점검한다.
- 다른 작업자(사람, 다른 AI)가 쓴 문서를 검토할 때.
- handoff-update 스킬의 마지막 단계에서 HANDOFF.md 를 점검할 때.

## 3. 절차

점검할 파일마다 아래 순서로 확인한다. 위반을 찾으면 그 자리에서 고치고 다시 확인한다.

1. 머리말 형식(docs/ 문서만): 첫 줄 `# {문서 제목}`, 이어서 "문서 목적", "대상 독자", "최종 수정", "관련 문서" 네 줄의 목록, 그다음 `## 목차` 가 있다. 내용을 고쳤으면 "최종 수정" 날짜를 오늘(YYYY-MM-DD)로 바꾼다.
2. 목차와 제목: `## 목차` 의 번호 목록과 본문 `## {번호}. {섹션명}` 제목이 글자까지 같다. 하위 제목은 `### {번호}.{번호} ...` 이다. 예외로 docs/05_작업지시서.md 4절~9절의 작업 항목 제목 `### {작업 ID} {작업명}` 은 허용한다(05 2.1).
3. 문체: 평서문 "~한다/~이다" 로 쓴다. 존댓말("~합니다/~하세요")은 화면 문구나 고지 문구를 인용할 때만 허용한다.
4. 용어: 용어의 원본은 docs/01_요구사항.md 9절 용어 정의 표 전체다. 03 2.1 의 "취득원가" 처럼 원본 문서가 정의한 용어도 허용한다. 표에 없는 동의어(예: 평단, 매입가, 평가액, 손익률, 보유량)만 위반으로 보고 표의 용어로 바꾼다.
5. 이모지와 장식 기호: 4.1 의 grep 명령을 실행해 출력이 없어야 한다. 출력된 문자는 하나씩 ASCII 나 한글로 바꾼다. 화살표는 ASCII "->" 만 허용한다.
6. 참조: 다른 문서의 내용을 길게 복사하지 않고 "docs/03_계산규칙.md 11절 참고" 처럼 문서와 절 번호로 참조한다. 복사한 내용은 원본이 바뀌면 틀린 내용이 되기 때문이다. 같은 규칙이 두 곳에 적혀 있으면 원본(AGENTS.md 2절 표)만 남기고 다른 쪽은 참조로 바꾼다.
7. 과장 문구: docs/04_디자인가이드.md 3절 7번의 예("스마트한", "한눈에 쏙", "똑똑한", "완벽한", "AI가 분석한") 같은 과장 표현이 없다.
8. SKILL.md 는 맨 위에 YAML 머리(name, description)를 두고, 본문은 목적, 트리거 상황, 절차, 산출물 절을 가진다(05 5절). 머리말 형식(1번)은 적용하지 않는다.

## 4. 산출물

### 4.1 검사 명령

프로젝트 루트에서 실행한다.

```
grep -nP "[^\x00-\x7F\x{AC00}-\x{D7A3}\x{3131}-\x{318E}]" {파일}
grep -nE "평단|매입가|평가액|손익률|보유량" {파일}
```

두 번째 명령은 동의어 후보를 찾는 보조 검사다. 이 SKILL.md 와 docs/05_작업지시서.md T2-01 처럼 금지 동의어를 예로 드는 줄은 위반이 아니다.

여러 파일을 한 번에 점검할 때:

```
for f in README.md AGENTS.md CLAUDE.md HANDOFF.md docs/*.md skills/*/SKILL.md; do echo "== $f"; grep -nP "[^\x00-\x7F\x{AC00}-\x{D7A3}\x{3131}-\x{318E}]" "$f"; done
```

목차와 본문 제목 비교(docs/ 문서마다, 출력이 없으면 일치):

```
diff <(awk '/^## 목차/{f=1;next} f&&/^$/{exit} f' {파일}) <(grep -E "^## [0-9]+\. " {파일} | sed 's/^## //')
```

### 4.2 점검 목록

- [ ] docs 문서는 머리말 네 줄과 `## 목차` 가 있다.
- [ ] 목차와 본문 `## ` 제목이 글자까지 같고 하위 제목 번호가 상위 절 번호를 따른다.
- [ ] 문서 문장은 평서문이고 존댓말은 화면 문구 인용에만 있다.
- [ ] 01 9절 표에 없는 동의어가 없다.
- [ ] 4.1 의 grep 출력이 없다.
- [ ] 다른 문서 내용을 길게 복사하지 않고 절 번호로 참조한다.
- [ ] 과장 문구가 없다.
- [ ] 고친 docs 문서의 "최종 수정" 날짜가 갱신되었다.

### 4.3 머리말 서식 예시

```
# 계산규칙

- 문서 목적: 포트폴리오 트래커의 모든 계산 공식과 검증 사례를 정의한다.
- 대상 독자: js/portfolio.js 를 구현하거나 수정하는 작업자
- 최종 수정: 2026-10-21
- 관련 문서: ./01_요구사항.md, ./02_설계문서.md

## 목차
1. 적용 범위와 원칙
2. 용어와 기호
```

### 4.4 좋은 예와 나쁜 예

| 좋은 예 | 나쁜 예 | 나쁜 이유 |
|---|---|---|
| 매도로 보유수량이 0 이 되면 평균단가를 0 으로 초기화한다. | 매도로 보유량이 0 이 되면 평단을 초기화해 주세요. | 용어 표에 없는 동의어, 존댓말 |
| 공식은 docs/03_계산규칙.md 4.1 을 따른다. | (03 의 공식과 예시 표를 그대로 복사해 붙인 문단) | 원본이 바뀌면 틀린 내용이 남는다 |
| 1단계 완료. 다음 작업은 T2-01 이다. | (체크표시 그림문자) 1단계 완료! 완벽하게 끝났습니다 | 장식 기호, 감탄, 과장, 존댓말 |
