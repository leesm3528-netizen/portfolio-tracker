# handoff-update

## 1. 목적

- HANDOFF.md 의 형식과 갱신 절차를 정한다. 형식의 원본은 AGENTS.md 9절이다.
- 다음 작업자(사람, 다른 AI, 새 세션의 Claude)는 이전 대화를 볼 수 없다. HANDOFF.md 하나만 읽고 현재 단계, 다음 작업, 막힌 곳을 알 수 있어야 한다. 그래서 세션이 언제 끊겨도 되도록 작업 단위마다 갱신한다.

## 2. 트리거 상황

- 작업 하나를 끝내고 커밋하기 직전(docs/05_작업지시서.md 1.3 의 3번).
- 작업을 끝내지 못하고 중간에 멈출 때.
- 단계 끝 보고 전(AGENTS.md 10절, 단계별 마지막 작업 ID 는 05 1.6).
- 사용자 결정(승인, M 항목 해소, 범위 변경)이 나온 직후.

## 3. 절차

1. 맨 위 한 줄 `최종 갱신: YYYY-MM-DD / 갱신자: {작업자 이름}` 을 갱신한다. 날짜는 오늘, 갱신자는 작업자 이름(예: Claude Code, Codex, 사람 이름)이다.
2. `## 현재 단계`: 단계 번호, 진행 중이거나 방금 마친 작업 ID, 승인 대기 여부를 쓴다. 단계의 마지막 작업을 마쳤으면 "{n}단계 완료" 와 승인 대기 여부(사용자가 연속 진행을 승인했으면 그 사실과 다음 단계 첫 작업 ID)를 쓴다.
3. `## 완료한 작업`: 맨 위에 `- {작업 ID} {작업명}: {만든 파일이나 바꾼 내용}. {검증 결과 요약}` 한 줄을 추가한다. 최근 것이 위다. 이전 줄은 지우지 않는다.
4. `## 다음 할 작업 (작업지시서 번호)`: 05 10절 표에서 선행 작업이 모두 "완료" 인 "대기" 작업을 표 순서대로 최대 3개 적는다. 형식은 `{번호}. {작업 ID} {작업명}` 이다. 3.1 에 상태 "미해결" 인 M 항목의 영향 작업은 빼고 그 이유를 알려진 문제에 적는다.
5. `## 알려진 문제`: 문제마다 내용, 재현 방법(명령이나 화면 조작), 관련 작업 ID 를 쓴다. 해결된 문제는 지운다.
6. `## 다음 작업자에게 주의사항`: 3.1 에 새로 추가된 미해결 M 항목, 승인 대기 결정, 커밋하지 않은 변경과 남은 단계를 쓴다. 작업이 끝나 의미가 없어진 주의사항은 지운다.
7. 05 10절 표의 상태 열과 HANDOFF.md 를 대조한다. 완료한 작업에 적은 ID 는 모두 "완료" 이고, 다음 할 작업에 적은 ID 는 모두 "대기" 여야 한다. 이번 작업을 마쳤다면 10절 상태를 "완료" 로, 작업 항목의 완료 기준을 "- [x]" 로 바꾼다.
8. skills/doc-writing-rules/SKILL.md 의 절차로 HANDOFF.md 를 점검한다(이모지 검사 포함).
9. 제목 확인: `grep -n "^## " HANDOFF.md` 의 출력이 4.1 의 5개 제목과 이름, 순서가 같아야 한다.

## 4. 산출물

### 4.1 HANDOFF.md 서식

제목 이름과 순서는 바꾸지 않는다.

```
최종 갱신: YYYY-MM-DD / 갱신자: {작업자 이름}

## 현재 단계

{단계 번호와 상태. 진행 중 작업 ID. 승인 대기 여부}

## 완료한 작업

- {작업 ID} {작업명}: {결과}. {검증 결과 요약}

## 다음 할 작업 (작업지시서 번호)

1. {작업 ID} {작업명}

## 알려진 문제

1. {내용}. 재현: {방법}. 관련 작업: {작업 ID}

## 다음 작업자에게 주의사항

1. {주의사항}
```

### 4.2 갱신 전후 예시

T2-01 을 마친 직후의 갱신이다(바뀐 부분만 보인다).

갱신 전:

```
## 현재 단계

1단계(문서 작성) 완료. ... 다음은 2단계(프로젝트 전용 스킬)이며 승인 대기 상태가 아니다.

## 완료한 작업

- T1-07 문서 간 불일치 해소: ...

## 다음 할 작업 (작업지시서 번호)

1. T2-01 doc-writing-rules 스킬 작성
```

갱신 후:

```
## 현재 단계

2단계(프로젝트 전용 스킬) 진행 중. T2-01 을 마쳤다. ... 승인 대기 상태가 아니다.

## 완료한 작업

- T2-01 doc-writing-rules 스킬 작성: skills/doc-writing-rules/SKILL.md. ... 이모지 검사 0 건.
- T1-07 문서 간 불일치 해소: ...

## 다음 할 작업 (작업지시서 번호)

1. T2-02 handoff-update 스킬 작성
2. T2-03 calc-rule-verify 스킬 문서 작성
3. T2-05 ui-verify 스킬 작성
```

T2-02, T2-03, T2-05 는 모두 선행 작업이 T2-01 하나이므로 함께 올라온다. T2-04 는 선행 작업 T2-03 이 "대기" 이므로 아직 적지 않는다.
