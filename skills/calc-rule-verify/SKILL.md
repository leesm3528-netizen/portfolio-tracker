# calc-rule-verify

## 1. 목적

- js/portfolio.js, js/rebalance.js, js/transactions.js 의 계산 결과가 docs/03_계산규칙.md 14절 검증 사례(C-01~C-15, R-01~R-06)와 같은지 확인한다.
- 계산 규칙의 원본은 03 이다. 코드를 고칠 때마다 같은 사례로 다시 확인해야 평균단가, 실현손익, 초과 매도 검증, 리밸런싱 판정이 몰래 바뀌는 것을 막을 수 있다.
- 검사 스크립트는 scripts/verify.mjs 다. 세부 동작의 원본은 docs/05_작업지시서.md 2.2 와 T2-04 다.

## 2. 트리거 상황

- js/portfolio.js, js/rebalance.js, js/transactions.js 중 하나를 바꿀 때(4단계 T4-01~T4-05 포함).
- docs/03_계산규칙.md 를 바꿀 때. 특히 14절 사례를 추가하거나 고칠 때.
- 계산 관련 버그(평균단가, 실현손익, 평가금액, 비중, 리밸런싱 금액, 초과 매도 판정)를 고칠 때.
- 4단계 끝 점검(T4-17)과 단계 끝 보고 전.

## 3. 절차

1. 프로젝트 루트에서 4.1 의 명령을 실행한다. Node 22 이상이 필요하다(`node --version` 으로 확인).
   - 구현 중간(T4-05 이전)에는 `--allow-missing` 을 붙인다. 아직 없는 모듈이나 함수를 쓰는 검사는 SKIP 이 되고 실패로 세지 않는다.
   - T4-05 이후에는 옵션 없이 실행하고 종료 코드가 0 이어야 한다.
   - 한 사례만 고칠 때는 사례 ID 나 묶음 접두(`C`, `R`)를 인자로 준다. 작업을 마치기 전에는 인자 없이 전체를 다시 실행한다.
2. FAIL 이 있으면 그 줄의 기대값과 실제값을 보고 코드 오류인지 문서 오류인지 판단한다. 판단 근거는 03 의 공식과 해당 사례 표다. 손으로 다시 계산해 본다.
3. 코드 오류면 코드를 고치고 1번부터 다시 실행한다.
4. 문서 오류(03 의 기대값이나 공식이 틀려 보임)면 docs/05_작업지시서.md 1.5 절차를 따른다. verify.mjs 의 기대값은 03 을 고치고 사용자 승인을 받기 전에 바꾸지 않는다. 기대값을 먼저 고치면 검증이 코드에 맞춰져 의미가 없어지기 때문이다.
5. verify.mjs 의 기대값이 03 원문과 다르게 옮겨진 것(전사 오류)이면 03 원문에 맞게 verify.mjs 를 고친다. 이때는 03 을 바꾸지 않으므로 승인이 필요 없다. 고친 사례 ID 를 HANDOFF.md 완료한 작업 줄에 적는다.
6. 03 14절에 사례를 추가하면 4.4 방법으로 verify.mjs 의 사례 데이터에도 같은 ID 로 추가한다.
7. 결과 요약(통과/실패/건너뜀 수)을 HANDOFF.md 완료한 작업 줄에 적는다(skills/handoff-update).

## 4. 산출물

### 4.1 실행 명령과 옵션

프로젝트 루트에서 실행한다(docs/05_작업지시서.md 2.2).

```
node skills/calc-rule-verify/scripts/verify.mjs
node skills/calc-rule-verify/scripts/verify.mjs C-01 R-03
node skills/calc-rule-verify/scripts/verify.mjs C
node skills/calc-rule-verify/scripts/verify.mjs --allow-missing
```

| 인자 | 의미 |
|---|---|
| 없음 | 모든 사례를 실행한다 |
| 사례 ID(예: `C-01`, `R-03`) | 그 사례만 실행한다. 여러 개를 줄 수 있다 |
| 묶음 접두 `C`, `R` | C 사례 전체 또는 R 사례 전체를 실행한다 |
| `--allow-missing` | 아직 없는 모듈이나 export 되지 않은 함수를 쓰는 검사를 SKIP 으로 표시하고 실패로 세지 않는다. T4-05 전까지만 쓴다 |
| 그 밖의 인자 | 03 에 없는 사례 ID 를 포함해 오류를 출력하고 종료 코드 1 로 끝난다 |

### 4.2 출력 예시

검사마다 한 줄이고 마지막 줄이 요약이다. 결과는 PASS, FAIL, SKIP 중 하나다.

```
사례 | 03절 | 항목 | 기대값 | 실제값 | 결과
C-01 | 14.2 | 최종 종목A quantity | 15 | 15 | PASS
C-01 | 14.2 | 최종 종목A avgCost | 11000 | 11000.5 | FAIL
C-02 | 14.3 | 표시 종목B 수익률 | "10.09" | 없음: portfolio.buildHoldings | SKIP
통과 1 / 실패 1 / 건너뜀 1
```

- 내부값은 절대 오차 0.000001 이하이면 같다고 본다. null 은 null 과만 같다. 표시값은 문자열이 정확히 같아야 한다(03 14.1).
- 표시값은 02 10절의 포매터 옵션과 부호 처리 규칙으로 만든 뒤 천 단위 쉼표, 끝의 `%`, 앞의 `+` 만 지우고 비교한다. `-` 는 남기므로 음수 표시와 "-0" 금지도 검사된다.
- 검사 중 예외가 나면 그 검사를 FAIL 로 기록하고 다음 검사를 계속한다. 모듈 파일은 있는데 불러오기에 실패하면(문법 오류 등) SKIP 이 아니라 FAIL 이다.

### 4.3 종료 코드

| 종료 코드 | 의미 |
|---|---|
| 0 | 모든 검사가 PASS 다. `--allow-missing` 을 붙였으면 FAIL 없이 PASS 와 SKIP 만 있다 |
| 1 | FAIL 이 하나 이상 있거나, `--allow-missing` 없이 SKIP 이 하나 이상 있거나, 알 수 없는 인자가 있다 |

js/ 가 없는 동안(T4-01 이전) 옵션 없이 실행하면 모든 검사가 SKIP 이고 종료 코드 1 이다. 이는 정상이다(05 T2-04).

### 4.4 사례 추가 방법

1. 03 14절에 다음 번호로 사례를 추가하고 사용자 승인을 받는다(03 1.2). 번호는 다시 쓰지 않는다.
2. scripts/verify.mjs 의 `CASES` 배열에 같은 ID 와 03 절 번호(`sec`)로 항목을 추가한다. 거래 행은 03 표의 열 순서(date, name, assetClass, type, quantity, price, fee)대로 적는다. id 는 스크립트가 "C16-0" 처럼 사례 ID 와 배열 인덱스로 붙인다.
3. 기대값은 반올림하지 않은 내부값이다. 무한소수는 `30500 / 3` 처럼 식으로 적는다. 표시값은 03 의 표시값 문자열을 쉼표 없이 그대로 적는다.
4. 단계별 상태, 거부 시도, 리밸런싱 표가 있으면 기존 사례(C-07 단계 실패, C-05 추가 거부, C-09 삭제 거부, R-01 리밸런싱)의 형식을 따라 적는다.
5. `node --check skills/calc-rule-verify/scripts/verify.mjs` 와 새 사례 ID 실행으로 확인한다.
