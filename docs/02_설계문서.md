## 1. 아키텍처 개요

### 1.1 형태

- 빌드 도구와 프레임워크가 없는 정적 단일 페이지 앱(SPA)이다.
- `index.html` 이 `css/style.css` 와 `<script type="module" src="js/main.js">` 하나만 불러온다. 나머지 모듈은 `main.js` 가 `import` 로 불러온다.
- 모든 경로는 상대 경로로 쓴다(`./js/...`, `js/...`). GitHub Pages 는 저장소 이름이 붙은 하위 경로(`/portfolio-tracker/`)에서 서비스하므로 `/` 로 시작하는 절대 경로를 쓰지 않는다.
- 서버 요청(fetch, XHR)은 없다. 저장은 브라우저 localStorage 와 사용자가 내려받는 JSON 파일뿐이다.
- 로컬 확인에는 `py -m http.server`(Windows Python 런처. 다른 환경은 `python3 -m http.server`) 같은 정적 파일 서버를 확인 용도로만 쓴다. ES 모듈은 `file://` 로 열리지 않기 때문이며, 앱 기능이 서버에 의존하는 것은 아니다.

### 1.2 상태 보유

- 앱 상태는 `main.js` 의 모듈 변수 하나(`state`)만 가진다. 형태는 저장 객체 `AppData`(5.5절)와 같다.
- 상태는 직접 수정하지 않는다. 변경 함수는 항상 새 객체나 새 배열을 반환하고, `main.js` 가 `state` 를 통째로 교체한다.
- 보유 현황, 자산 비중, 리밸런싱 결과 같은 파생 데이터는 저장하지 않는다. 상태가 바뀔 때마다 거래 전체를 처음부터 다시 계산한다.

- 공통 상수(자산군 목록과 표시 이름 등)는 파일구조가 고정되어 있으므로 의존성의 가장 아래인 `portfolio.js` 에 둔다. 다른 모듈은 같은 값을 다시 정의하지 않고 가져다 쓴다.

- 사용자 입력 문자열(종목명, 파일에서 읽은 값)은 `textContent` 나 `value` 로만 화면에 넣는다. `innerHTML` 에 사용자 값을 넣지 않는다.
- 사용하지 않는 export, 함수, 변수를 남기지 않는다. 7절에 없는 공개 함수를 추가하려면 먼저 이 문서를 수정한다.
- 모듈 밖(다른 앱 모듈 또는 verify.mjs)에서 쓰는 이름만 export 한다. 7절 표에서 "내부" 로 표시한 이름은 그 모듈 안에서만 쓰고 export 하지 않는다(14절 D-18).

## 3. 모듈 의존 방향

```
[화면 계층]    main.js
                 |
       +---------+----------+----------------+--------------+
       |         |          |                |              |
       v         v          v                v              v
     ui.js   storage.js  transactions.js  rebalance.js  portfolio.js
       |         |          |                |
       |         +--> transactions.js        |
       |         +--> rebalance.js           |
       |         +--> portfolio.js           |
       |                    |                |
       v                    v                v
[도메인 계층]  portfolio.js (상수, 순수 계산. import 없음)
```

import 관계 목록(이 표에 없는 import 는 금지한다):

| 모듈 | import 하는 모듈 |
| --- | --- |
| `main.js` | `ui.js`, `storage.js`, `transactions.js`, `portfolio.js`, `rebalance.js` |
| `ui.js` | `portfolio.js` (상수만) |
| `storage.js` | `transactions.js`, `rebalance.js`, `portfolio.js` |
| `transactions.js` | `portfolio.js` |
| `rebalance.js` | `portfolio.js` |
| `portfolio.js` | 없음 |

- 순환 의존은 금지한다.
- 화살표 방향은 항상 화면 계층 -> 저장 계층 -> 도메인 계층이다. 도메인 모듈은 `ui.js`, `storage.js`, `main.js` 를 import 하지 않는다.

## 4. 오류 처리 규칙

모든 모듈에서 아래 방식 하나로 통일한다.

### 4.1 Result 객체

사용자 입력이나 외부 데이터(localStorage, 불러온 파일) 때문에 실패할 수 있는 함수는 예외를 던지지 않고 `Result` 를 반환한다.

```
성공: { ok: true, value: <결과값> }
실패: { ok: false, error: Message }
Message = { code: string, params: object }
```

예: `{ ok: false, error: { code: "VE-09", params: { date: "2026-05-03", name: "종목E", held: 10 } } }`

- `code` 는 docs/01_요구사항.md 5절의 메시지 ID(VE-xx, VD-xx, IN-xx, C-xx)다. `params` 는 그 문구의 치환 자리에 넣을 값이며, 필드 이름과 치환 자리의 대응은 11절 표가 정한다. 치환할 값이 없으면 `params` 는 `{}` 다.
- `params` 의 값은 형식화하지 않은 원래 값이다. 숫자는 반올림하지 않은 number, 자산군과 구분은 저장 키(`"stock"`, `"buy"` 등), 날짜는 `"YYYY-MM-DD"` 문자열이다. 다른 메시지를 넣는 자리({상세}, {원인})에는 `Message` 객체를 그대로 넣는다.
- 계산과 검증 모듈(portfolio.js, rebalance.js, transactions.js, storage.js)은 화면 문장, 머리말, 숫자 표시 문자열을 만들지 않는다. 문장은 `ui.js` 가 01 5절 문구로 만든다(4.3).
- 반환값이 필요 없는 성공은 `{ ok: true, value: null }` 이다.
- 하위 함수의 실패를 감쌀 때는 문장을 덧붙이지 않는다. 11절에 정한 대로 `code` 를 바꾸거나(예: VE-25 -> VE-09) 하위 `Message` 를 `params` 에 넣는다(예: VE-18 의 `detail`).
- 예외: `portfolio.calcPositions` 의 실패 Result 는 초과 매도 위치를 알리는 `violation` 필드를 더 가진다(7.1). 이 필드는 `transactions.js` 가 메시지 ID 를 고르는 데만 쓴다.
- `Message` 는 확인 대화상자 문구(C-01, C-02)와 완료 안내(IN-04)를 `ui.js` 에 넘길 때도 같은 형태로 쓴다.

### 4.2 예외를 던지는 경우

- 검증을 통과한 상태에서는 일어날 수 없는 상황(불변 조건 위반, 프로그래밍 오류)만 `Error` 를 던진다. 예: 검증된 `state` 로 `calcPositions` 를 호출했는데 실패한 경우.
- 사용자 입력 오류를 `throw` 로 처리하지 않는다.

### 4.3 화면 표시

- `Result` 의 실패는 `main.js` 가 `ui.showMessage(area, error, "error")` 로 해당 영역의 메시지 줄에 표시한다. 상태는 바꾸지 않는다.
- `ui.js` 는 01 5.2~5.4 의 문구 표를 내부 상수 `MESSAGES`(메시지 ID -> 문구)로 가진다. `Message` 를 받으면 `params` 의 각 값을 11절이 정한 10절 표시 함수로 형식화해 치환 자리에 넣고, 04 13.1 의 머리말("오류: ", "안내: ")을 `kind` 에 따라 앞에 붙인다. 확인 대화상자 문구에는 머리말을 붙이지 않는다.
- 01 5.5 의 정적 문구(IN-01~IN-03, IN-05, IN-06)는 index.html 에 있고 `MESSAGES` 에 넣지 않는다. `ui.js` 는 그 요소의 hidden 속성만 바꾼다.
- `alert()` 는 쓰지 않는다. 확인이 필요한 동작(거래 삭제, 불러오기 교체)만 `ui.confirmAction` 을 쓴다.

## 5. 데이터 구조

필드 정의는 확정된 형식이며, 이 절에 없는 필드나 값은 만들지 않는다.

### 5.1 거래 Transaction

| 필드 | 타입 | 제약 |
| --- | --- | --- |
| `id` | string | `crypto.randomUUID()` 로 생성. 비어 있지 않은 문자열. 목록 안에서 중복 불가 |
| `date` | string | `"YYYY-MM-DD"`. 실제 존재하는 날짜 |
| `name` | string | 앞뒤 공백 제거 후 비어 있지 않음. 종목의 식별자 |
| `assetClass` | string | `"stock"`, `"bond"`, `"cash"`, `"other"` 중 하나 |
| `type` | string | `"buy"`, `"sell"` 중 하나 |
| `quantity` | number | 양의 정수(`Number.isSafeInteger` 이고 1 이상) |
| `price` | number | 0보다 큰 유한한 수. 소수 허용 |
| `fee` | number | 0 이상의 유한한 수(원) |

추가 제약:

- 같은 `name` 은 하나의 `assetClass` 만 가진다.
- 현금: `name` 이 `"현금"` 이면 `assetClass` 는 `"cash"`, `price` 는 `1` 이어야 한다. `quantity` 는 금액(원)이다.
- 거래 목록 전체를 처리 순서(날짜 오름차순, 같은 날짜는 배열 순서)로 다시 계산했을 때 어떤 매도도 그 시점 보유수량을 넘으면 안 된다.
- 필드 순서와 추가 필드: 위 8개 필드 외의 키가 있으면 형식 오류다.

예시:

```json
{
  "id": "3f2b8c1e-6a4d-4e7b-9c0a-1d2e3f4a5b6c",
  "date": "2026-10-01",
  "name": "삼성전자",
  "assetClass": "stock",
  "type": "buy",
  "quantity": 10,
  "price": 10000,
  "fee": 0
}
```

### 5.2 거래 입력 원본 TransactionInput

`ui.js` 가 거래 입력 폼에서 읽어 `main.js` 로 넘기는 값이다. 모든 값은 폼에 입력된 그대로의 문자열이다.

```
{ date: string, name: string, assetClass: string, type: string,
  quantity: string, price: string, fee: string }
```

- `fee` 가 빈 문자열이면 0 으로 해석한다(01 FR-01 기준 4). 다른 숫자 칸의 빈 문자열은 오류다.
- 숫자 해석은 `portfolio.parseNumber` 를 쓴다(7.1절).
- 숫자 입력칸에 브라우저가 숫자로 해석하지 못한 글자가 있으면 그 칸의 값은 "NaN" 이다(7.5절 숫자 입력칸 값 읽기).

### 5.3 현재가 Prices

```json
{ "삼성전자": 13000, "국고채10년": 10250.5 }
```

- 키: 종목명(거래의 `name` 과 같은 문자열). 값: 0보다 큰 유한한 수.
- 키가 없으면 "현재가 미입력" 이다. 0 이나 빈 값을 저장하지 않는다.
- `"현금"` 키는 저장하지 않는다. 현금의 현재가는 항상 1 이다.
- 거래가 하나도 없는 종목의 키는 `prunePrices` 로 제거한다(거래 삭제 후, 불러오기 후).

### 5.4 목표 비중 Targets

```json
{ "stock": 60, "bond": 30, "cash": 10, "other": 0 }
```

- 키는 정확히 `stock`, `bond`, `cash`, `other` 4개. 빠지거나 추가된 키는 형식 오류다.
- 값: 0 이상 100 이하의 수, 소수 첫째 자리까지. 기본값은 모두 0.
- 사용자 확정 규칙 "목표 비중 합계는 반드시 100" 은 리밸런싱 계산 조건으로 해석한다. 저장 시에는 합계가 100 이 아니어도 된다(입력 중인 상태를 저장한다). JSON 불러오기도 합계를 검사하지 않는다(5.7). 합계가 100 이 아니면 리밸런싱을 계산하지 않고 VE-15 를 안내한다.
- 소수 첫째 자리 판정: `Math.abs(v * 10 - Math.round(v * 10)) < 1e-9`.

### 5.6 JSON 내보내기 파일

- 내용은 5.5절 저장 객체와 같다. `JSON.stringify(data, null, 2)` 로 들여쓰기 2칸.
- 파일 이름: `portfolio-tracker-YYYY-MM-DD.json` (내보낸 날의 브라우저 로컬 날짜).
- MIME 타입: `application/json`.

### 5.7 불러오기 검증 규칙

localStorage 에서 읽은 값과 불러온 파일 모두 `storage.parseData` 로 같은 규칙을 적용한다. 순서대로 검사하고 처음 실패한 항목의 `Message` 를 반환한다. 메시지 ID 의 문구는 01 5.4 다.

1. 텍스트가 JSON 으로 해석된다. 실패하면 VE-17.
2. 최상위 값이 객체(배열과 null 아님)다. 실패하면 VE-18(`detail` VD-01).
3. `version` 이 숫자 `1` 이다. 키가 없거나 다른 값이면 VE-19. 버전이 다른 파일(예: 키 구성이 다른 version 2)이 형식 오류가 아니라 버전 오류로 보이도록 키 집합 검사보다 먼저 한다.
4. 키가 정확히 `version`, `transactions`, `prices`, `targets` 이다. 실패하면 VE-18(VD-01).
5. `transactions` 가 배열이다(실패하면 VE-18(VD-02)). 각 항목이 `transactions.validateTransactionFields` 를 통과한다(5.1절 필드 제약). 실패하면 VE-18(VD-03, `index` 는 1부터, `cause` 는 항목 검사의 `Message`).
6. 거래 `id` 가 중복되지 않는다. 실패하면 VE-18(VD-04).
7. `transactions.validateTransactionList` 를 통과한다(자산군 일관성, 초과 매도 없음). 실패하면 VE-18(`detail` 은 VE-07 또는 VE-25 `Message`).
8. `prices` 가 객체(배열과 null 아님)이고 모든 값이 0보다 큰 유한한 수다. 실패하면 VE-18(VD-05).
9. `targets` 가 `rebalance.validateTargets` 를 통과한다. 실패하면 VE-18(VD-06). 목표 비중 합계는 검사하지 않는다(5.4).
10. 통과하면 `prices` 에 `prunePrices` 를 적용한 객체를 `value` 로 반환한다.

불러오기 동작:

- 검증에 실패하면 상태를 바꾸지 않고 `#data-message` 에 오류를 표시한다.
- 검증에 성공하면 확인 대화상자(C-02)를 띄우고, 확인한 경우에만 기존 상태 전체를 교체한다. 일부 병합은 하지 않는다.

저장 데이터 손상 처리(앱 시작 시):

- localStorage 값이 위 검사에 실패하거나 localStorage 접근 자체가 실패하면 `loadData` 는 VE-21 로 실패한다. `main.init` 은 VE-21 을 `#data-message` 에 오류로 표시하고 빈 데이터로 시작한다.
- 손상된 값은 지우지 않고 그대로 둔다. 사용자가 처음 변경할 때 `commit` 의 저장으로 덮어쓴다. 별도 백업 키는 만들지 않는다. 사용자는 VE-21 안내대로 백업 JSON 을 불러와 복구한다.

## 6. 파생 데이터 구조

모두 저장하지 않고 상태에서 매번 계산한다. 계산 방식은 docs/03_계산규칙.md 를 따르며 이 문서에는 공식을 적지 않는다. 숫자 값은 반올림하지 않은 원래 값이다.

### 6.1 종목 상태 Position

`portfolio.calcPositions` 의 결과 배열 원소. 거래를 처리 순서대로 재생한 뒤 종목별 최종 상태다.

| 필드 | 타입 | 의미 |
| --- | --- | --- |
| `name` | string | 종목명 |
| `assetClass` | string | 자산군 키 |
| `quantity` | number | 보유수량(0 이상 정수) |
| `avgCost` | number | 평균단가. 보유수량 0 이면 0 |
| `realizedPnl` | number | 누적 실현손익(원) |

### 6.2 보유 현황 행 HoldingRow

`portfolio.buildHoldings` 의 결과 배열 원소. 보유 현황 표의 한 행이다.

| 필드 | 타입 | 의미 |
| --- | --- | --- |
| `name` | string | 종목명 |
| `assetClass` | string | 자산군 키 |
| `quantity` | number | 보유수량 |
| `avgCost` | number | 평균단가 |
| `price` | number 또는 null | 평가에 쓴 현재가. 현금은 1, 미입력이면 평균단가. 보유수량 0 이면 null |
| `priceMissing` | boolean | 현재가 미입력 여부. 현금과 보유수량 0 종목은 false |
| `marketValue` | number | 평가금액. 보유수량 0 이면 0 |
| `costBasis` | number | 보유수량 x 평균단가 |
| `unrealizedPnl` | number | 평가손익 |
| `returnRate` | number 또는 null | 수익률(%). 보유수량 0 이면 null |
| `realizedPnl` | number | 누적 실현손익 |

- 정렬: 자산군 순서(`ASSET_CLASSES` 순서) -> 같은 자산군 안에서는 종목명 `localeCompare(b, "ko")` 오름차순.
- 보유수량 0 인 종목도 실현손익 확인을 위해 표에 포함한다. 이 행의 현재가, 평가금액, 평가손익, 수익률 칸은 `-` 로 표시하고 현재가 입력칸을 두지 않는다.

### 6.3 자산군별 평가금액 ClassValues

`portfolio.sumValueByAssetClass` 의 결과.

```json
{ "stock": 7000000, "bond": 2000000, "cash": 1000000, "other": 0 }
```

4개 키를 항상 가진다. 리밸런싱 계산의 입력이기도 하다.

### 6.4 자산 비중 AllocationResult

`portfolio.buildAllocation` 의 결과.

```
{
  totalValue: number,          // 총평가금액
  rows: AllocationRow[]        // 항상 4개, ASSET_CLASSES 순서
}
AllocationRow = {
  assetClass: string,
  value: number,               // 자산군 평가금액
  weight: number | null        // 비중(%). totalValue 가 0 이면 null
}
```

### 6.5 리밸런싱 결과 RebalanceResult

`rebalance.calcRebalance` 가 성공할 때의 `value`.

```
{
  totalValue: number,          // 총평가금액
  rows: RebalanceRow[]         // 항상 4개, ASSET_CLASSES 순서
}
RebalanceRow = {
  assetClass: string,
  currentValue: number,        // 자산군 현재 평가금액
  targetWeight: number,        // 목표 비중(%)
  targetValue: number,         // 목표 금액
  amount: number,              // 리밸런싱 금액(부호 있음. 양수 매수, 음수 매도)
  tradeAmount: number,         // amount 의 절댓값. 화면 표시용
  action: "buy" | "sell" | "hold"
}
```

- `action` 판정: `amount >= 0.5` 이면 `"buy"`, `amount <= -0.5` 이면 `"sell"`, 그 사이(원 단위 반올림 결과 0)는 `"hold"`. 이 기준은 10절의 원 단위 반올림 방식(0.5 는 0 에서 먼 쪽으로)과 일치한다.

## 7. 모듈별 공개 함수

표기: `함수명(매개변수: 타입) -> 반환 타입`. `Result<T>` 는 4.1절 형식이다. 모든 함수는 인자를 수정하지 않는다. 실패 시 반환하는 메시지 ID 와 `params` 는 11절 표가 정한다.

### 7.1 portfolio.js

상수:

| 이름 | 값 |
| --- | --- |
| `ASSET_CLASSES` | `["stock", "bond", "cash", "other"]` (화면과 계산의 자산군 순서) |
| `ASSET_CLASS_LABELS` | `{ stock: "주식", bond: "채권", cash: "현금", other: "기타" }` |
| `TRANSACTION_TYPES` | `["buy", "sell"]` |
| `TRANSACTION_TYPE_LABELS` | `{ buy: "매수", sell: "매도" }` |
| `CASH_NAME` | `"현금"` |
| `CASH_PRICE` | `1` |

함수:

| 함수 | 반환 | 설명과 오류 처리 |
| --- | --- | --- |
| `parseNumber(raw: string)` | number 또는 null | 앞뒤 공백 제거 후 빈 문자열이면 null. `Number(raw)` 가 유한한 수가 아니면 null. 범위 검사는 호출한 쪽이 한다 |
| `sortTransactions(transactions: Transaction[])` | Transaction[] | 처리 순서(날짜 오름차순, 같은 날짜는 원래 배열 순서)로 정렬한 새 배열. 안정 정렬 |
| `calcPositions(transactions: Transaction[])` | Result<Position[]> | `sortTransactions` 순서로 재생해 종목별 상태 계산. 매도 수량이 그 시점 보유수량을 넘으면 첫 위반 거래에서 멈추고 VE-25 로 실패한다. 이 실패 Result 는 `violation` 필드를 더 가진다(아래). 필드 형식과 자산군 일관성은 검사하지 않는다(transactions.js 담당) |
| `buildHoldings(positions: Position[], prices: Prices)` | HoldingRow[] | 6.2절 행 생성과 정렬 |
| `sumValueByAssetClass(holdings: HoldingRow[])` | ClassValues | 자산군별 평가금액 합계. 4개 키 모두 포함 |
| `calcTotalValue(classValues: ClassValues)` | number | 총평가금액. `buildAllocation` 과 `calcRebalance` 가 공통으로 사용 |
| `buildAllocation(classValues: ClassValues)` | AllocationResult | 6.4절 |
| `updatePrice(prices: Prices, name: string, raw: string)` | Result<Prices> | 현재가 입력 규칙의 원본이다. `raw` 를 앞뒤 공백 제거 후 빈 문자열이면 해당 키를 지운 새 객체(현재가 미입력으로 되돌림). `parseNumber` 결과가 0보다 큰 수면 설정한 새 객체. 그 외(0, 음수, 숫자 아님)는 VE-12 로 실패. `name` 이 `CASH_NAME` 이면 바꾸지 않은 객체를 그대로 성공 반환 |
| `prunePrices(prices: Prices, transactions: Transaction[])` | Prices | 거래가 없는 종목과 `CASH_NAME` 키를 뺀 새 객체 |

`calcPositions` 실패 Result 의 형식:

```
{
  ok: false,
  error: { code: "VE-25", params: { date, name, quantity, held } },
  violation: { index, date, name, quantity, held }
}
```

- `index`: 처음으로 보유수량을 초과한 매도 거래의 입력 배열(정렬 전) 위치(0부터).
- `date`, `name`: 그 거래의 날짜와 종목명. `quantity`: 그 거래의 매도 수량. `held`: 그 거래 직전의 보유수량.
- `error.params` 와 `violation` 은 같은 값을 가진다. `violation` 은 메시지 ID 를 고르는 쪽(7.2)이 읽고, `error` 는 그대로 표시할 수 있는 기본 메시지다.

### 7.2 transactions.js

| 함수 | 반환 | 설명과 오류 처리 |
| --- | --- | --- |
| `createTransaction(input: TransactionInput)` | Result<Transaction> | 문자열을 해석(`name` trim, 숫자는 `parseNumber`, 빈 `fee` 는 0)하고 `crypto.randomUUID()` 로 `id` 를 붙인 뒤 `validateTransactionFields` 결과를 반환 |
| `validateTransactionFields(value: unknown)` | Result<Transaction> | 거래 한 건의 5.1절 필드 제약과 현금 규칙 검사. 01 5.1 의 항목 검사 순서(VE-23, VE-26, VE-01, VE-02, VE-03, VE-22, VE-04, VE-05, VE-06, VE-08)로 검사하고 첫 번째 위반으로 실패. VE-23 의 `key` 는 정의되지 않은 키가 있으면 그 첫 키(`Object.keys` 순서), 없으면 5.1절 필드 순서로 처음 빠진 키다. 객체(배열과 null 아님)가 아닌 값은 키가 없는 것으로 보아 VE-23(`key` "id")으로 실패 |
| `validateTransactionList(transactions: Transaction[])` | Result<Transaction[]> | 같은 종목명의 자산군 일관성 검사(위반 시 VE-07) 후 `portfolio.calcPositions` 로 초과 매도 검사. `calcPositions` 의 실패 Result 는 `violation` 을 포함해 그대로 반환한다. 통과하면 받은 배열을 그대로 반환 |
| `addTransaction(transactions: Transaction[], tx: Transaction)` | Result<Transaction[]> | 배열 끝에 추가한 새 배열을 `validateTransactionList` 로 검사. 실패 Result 에 `violation` 이 있으면 `violation.index` 가 `transactions.length`(추가한 거래의 위치)일 때 VE-09, 아니면 VE-10 으로 바꿔 반환한다. `violation` 이 없으면(VE-07) 그대로 반환한다 |
| `deleteTransaction(transactions: Transaction[], id: string)` | Result<Transaction[]> | `id` 가 없으면 VE-24 로 실패. 해당 거래를 뺀 새 배열을 `validateTransactionList` 로 검사하고, 실패 Result 에 `violation` 이 있으면 VE-11 로 바꿔 반환한다 |

- `addTransaction`, `deleteTransaction` 이 바꿔 반환하는 실패 Result 에는 `violation` 을 남기지 않는다.
- 거래 수정 기능은 MVP 에 없다. 고치려면 삭제 후 다시 입력한다.
- 과거 날짜 거래 추가와 삭제 모두 전체 목록을 처음부터 다시 검사하므로 이후 매도의 초과 여부가 함께 검증된다.

### 7.3 rebalance.js

| 이름 | 반환 | 설명과 오류 처리 |
| --- | --- | --- |
| `TARGET_TOTAL` | 상수 `100` | 내부(export 하지 않음). 목표 비중 합계 기준값 |
| `createDefaultTargets()` | Targets | 4개 자산군 모두 0 인 새 객체 |
| `parseTargetInput(raw: string)` | Result<number> | 목표 비중 입력 규칙의 원본이다. 앞뒤 공백 제거 후 빈 문자열, 숫자가 아닌 값, 0 미만 또는 100 초과는 VE-13 으로 실패. 소수 둘째 자리 이상(5.4절 판정)은 VE-14 로 실패. 그 외 성공. 빈칸은 0 으로 바꾸지 않는다. 실패하면 `main.js` 는 저장하지 않으므로 이전 저장값이 유지된다(입력칸은 type=number 라 값을 지우는 도중 빈 문자열이 넘어오며, 이때 저장값을 0 으로 덮지 않기 위해서다. 입력 도중 "-" 처럼 숫자로 해석되지 않는 값은 7.5절 숫자 입력칸 값 읽기 규칙으로 "NaN" 이 넘어와 VE-13 이 된다) |
| `validateTargets(value: unknown)` | Result<Targets> | 5.4절 검사(키 4개 정확히, 각 값 범위와 자릿수). 실패하면 VD-06. 합계는 검사하지 않음 |
| `sumTargets(targets: Targets)` | number | 각 값을 10배 해 정수로 반올림한 합을 10으로 나눈 값. 소수 오차 없이 합계를 비교하기 위한 처리이며 입력값 자체가 소수 첫째 자리까지라 값이 바뀌지 않는다 |
| `calcRebalance(classValues: ClassValues, targets: Targets)` | Result<RebalanceResult> | 먼저 `calcTotalValue` 가 0 이면 VE-16 으로 실패. 다음 `sumTargets` 가 `TARGET_TOTAL` 이 아니면 VE-15(`sum` 에 합계)로 실패. 그 외 6.5절 결과 |

숫자 입력칸 값 읽기: type=number 입력칸에 브라우저가 숫자로 해석하지 못한 글자가 있으면(`validity.badInput`) `value` 가 빈 문자열이 된다. 빈칸(수수료 0, 현재가 미입력)과 구분하도록 `ui.js` 는 이때 그 칸의 값으로 문자열 `"NaN"` 을 넘긴다. `parseNumber` 가 null 을 반환하므로 숫자가 아닌 값의 오류(VE-04, VE-05, VE-06, VE-12, VE-13)가 된다(05 3.1 M-32).

`MessageArea` 는 `"transaction"`, `"transactions"`, `"holdings"`, `"targets"`, `"data"` 중 하나이며 각각 `#tx-message`, `#transactions-message`, `#holdings-message`, `#targets-message`, `#data-message` 에 대응한다. 리밸런싱 안내(`#rebalance-message`)는 `renderApp` 이 ViewModel 의 `rebalance` 로 직접 그린다.

`UiHandlers`(main.js 가 구현):

```
{
  onAddTransaction(input: TransactionInput): void,
  onDeleteTransaction(id: string): boolean,     // 삭제해 상태를 바꿨으면 true. 취소나 거부면 false
  onPriceChange(name: string, raw: string): void,
  onTargetInput(assetClass: string, raw: string): void,
  onExport(): void,
  onImportFile(file: File): void
}
```

렌더 뒤 포커스 규칙(01 NFR-04, 04 14.2):

- 거래 삭제: `#transactions-body` 의 click 위임 핸들러는 누른 삭제 버튼이 몇 번째 행인지 기억하고 `onDeleteTransaction(id)` 를 호출한다. 반환값이 true 면(이때 `commit` 과 렌더가 이미 끝났다) 같은 순번 행(삭제한 행의 다음 행)의 삭제 버튼에, 그 행이 없으면 `#transactions-heading` 에 포커스를 옮긴다. false 면 포커스를 옮기지 않는다.
- 다시 그리기: `renderApp` 은 그리기 전에 `document.activeElement` 가 `#holdings-body` 또는 `#transactions-body` 안에 있으면 그 요소의 `data-action` 과 `data-name`(거래 행은 `data-id`)을 기억하고, 그린 뒤 같은 속성 값을 가진 새 요소가 있으면 그 요소에 포커스를 옮긴다. 현재가 입력 뒤 Tab 으로 다음 입력칸에 간 경우 포커스가 사라지지 않게 하기 위해서다.

내부 함수와 상수(export 하지 않음): `MESSAGES`(4.3절), 메시지 문장 만들기, 폼 값 읽기, 영역별 렌더 함수, 숫자 표시 함수(10절), 오늘 날짜 문자열 함수(폼 기본값과 내보내기 파일 이름에 공통 사용).

### 7.6 main.js

export 하지 않는다. 내부 구성:

- `state`: 현재 AppData.
- `init()`: `storage.loadData()` -> 실패면 빈 데이터(`createEmptyData()`)로 시작하고 `#data-message` 에 실패 `error`(VE-21)를 오류로 표시 -> `ui.setTargetInputs` -> `ui.bindEvents(handlers)` -> `render()`.
- `commit(nextData)`: `state` 교체 -> `storage.saveData` (실패하면 `#data-message` 에 VE-20 오류, 화면 상태는 유지) -> `render()`.
- `buildView(data)`: `calcPositions`(실패하면 4.2절에 따라 throw) -> `buildHoldings` -> `sumValueByAssetClass` -> `buildAllocation` -> `sumTargets` -> `calcRebalance` 로 ViewModel 생성.
- `render()`: `ui.renderApp(buildView(state))`.
- `handlers`: `UiHandlers` 구현(8절).

## 8. 데이터 흐름

기본 흐름은 모든 변경에 같다.

```
입력(ui 이벤트) -> 검증(transactions/portfolio/rebalance/storage) -> 상태 교체(main)
  -> 저장(storage.saveData) -> 재계산(main.buildView) -> 렌더(ui.renderApp)
```

검증이 실패하면 상태 교체 이후 단계는 실행하지 않고 해당 영역에 오류를 표시한다. 성공하면 해당 영역의 메시지를 지운다.

| 동작 | 이벤트 | 처리 |
| --- | --- | --- |
| 거래 추가 | `#transaction-form` submit (기본 동작 막음) | `createTransaction` -> `addTransaction` -> `commit` -> `resetTransactionForm`. 실패는 `"transaction"` 영역 |
| 거래 삭제 | 거래 내역 표의 삭제 버튼 click | `confirmAction({ code: "C-01", params: { date, name, type, quantity } })` -> 취소면 false 반환 -> `deleteTransaction` -> 실패면 `"transactions"` 영역에 오류, false 반환 -> 성공이면 `prunePrices` -> `commit` -> true 반환. 포커스는 7.5절 |
| 현재가 입력 | 보유 현황 표의 현재가 입력칸 change (입력칸을 벗어나거나 Enter) | `updatePrice` -> `commit`. 실패는 `"holdings"` 영역. 표가 다시 그려지므로 input 이벤트가 아닌 change 이벤트를 쓴다 |
| 목표 비중 입력 | `#target-*` input | `parseTargetInput` -> 새 `targets` 로 `commit`. 실패하면 `#targets-message` 오류, 상태와 저장값 유지(7.3절) |
| 내보내기 | `#export-button` click | `serializeData(state)` -> `downloadJson` |
| 불러오기 | `#import-button` click 이 `#import-file` 을 연다. `#import-file` change | `file.text()` -> `parseData` -> 실패면 `"data"` 영역 오류 -> 성공이면 `confirmAction({ code: "C-02", params: { currentCount, fileCount } })` -> 확인 시 `commit` -> `setTargetInputs` -> `"data"` 영역에 IN-04 안내. 끝나면 같은 파일을 다시 고를 수 있도록 `#import-file` 의 값을 비운다 |
| 시작 | `DOMContentLoaded` 불필요(모듈 스크립트는 지연 실행) | `init()` |

| `message-info` | 메시지 줄 안내 상태 |
| `price-missing` | "현재가 미입력" 표시 |

`value-up`/`value-down` 판정은 표시 반올림 결과 기준이다. 표시가 0 이면 어느 클래스도 붙이지 않는다. 대상 칸: 평가손익, 수익률, 실현손익.

## 10. 숫자 표시 형식

값 종류별 반올림 자릿수의 원본은 docs/03_계산규칙.md 13.2, 반올림 방식은 13.1 이다. 이 절은 구현 방법만 정한다. 표시 함수는 `ui.js` 내부에만 둔다. 계산과 검증 모듈은 숫자를 형식화하지 않는다(4.1).

| 내부 함수 | 대상 | 포매터 `Intl.NumberFormat("ko-KR", 옵션)` 의 옵션 | 부호 |
| --- | --- | --- | --- |
| `formatWon(n)` | 금액(평가금액, 총평가금액, 자산군 평가금액, 목표 금액, 리밸런싱 금액) | `{ maximumFractionDigits: 0 }` | 음수만 "-" |
| `formatSignedWon(n)` | 평가손익, 실현손익 | `{ maximumFractionDigits: 0 }` | 양수 "+", 음수 "-" |
| `formatAvgCost(n)` | 평균단가 | `{ minimumFractionDigits: 2, maximumFractionDigits: 2 }` | 음수만 "-" |
| `formatPrice(n)` | 현재가, 거래 가격, 수수료 | `{ minimumFractionDigits: 0, maximumFractionDigits: 2 }` | 음수만 "-" |
| `formatQuantity(n)` | 수량, 보유수량, 메시지 안의 수량과 건수 | `{ maximumFractionDigits: 0 }` | 없음(음수가 생기지 않음) |
| `formatPercent(n)` | 비중(표 안. `%` 를 붙이지 않음) | `{ minimumFractionDigits: 2, maximumFractionDigits: 2 }` | 음수만 "-" |
| `formatSignedPercent(n)` | 수익률(표 안. `%` 를 붙이지 않음) | `{ minimumFractionDigits: 2, maximumFractionDigits: 2 }` | 양수 "+", 음수 "-" |
| `formatTargetSum(n)` | 목표 비중 합계(`#target-sum` 은 결과 뒤에 "%" 를 붙인다), VE-15 의 {합계} | `{ minimumFractionDigits: 1, maximumFractionDigits: 1 }` | 음수만 "-" |

부호 처리 규칙(모든 함수 공통):

1. 포매터에 `Math.abs(n)` 을 넣어 숫자 문자열 s 를 만든다.
2. s 에 0 이 아닌 숫자가 없으면(표시값이 0) 부호 없이 s 를 쓴다. 그래서 -0.3 은 "0" 이 되고 "-0" 은 나오지 않는다(03 13.1).
3. 그 외에 n < 0 이면 "-" + s 를 쓴다.
4. "양수 +" 함수는 그 외에 n > 0 이면 "+" + s 를 쓴다(01 FR-13 기준 5, 04 8.4).

- `signDisplay` 옵션은 쓰지 않는다. `signDisplay: "negative"` 는 Intl.NumberFormat v3 기능이라 01 NFR-02 의 최소 지원 브라우저(Chrome 92, Edge 92, Firefox 95)에서 포매터 생성 시 RangeError 가 난다. `"exceptZero"` 도 반올림 후 0 이 되는 값의 처리가 구현 버전마다 다를 수 있으므로 쓰지 않는다. 위 방식은 오래된 브라우저에도 있는 `minimumFractionDigits`, `maximumFractionDigits` 옵션만 쓴다.
- 반올림은 `Intl.NumberFormat` 의 기본 반올림(halfExpand)을 절댓값에 적용한다. 그래서 0.5 경계는 0 에서 먼 쪽으로 반올림된다(03 13.1). `Math.round` 로 표시값을 만들지 않는다(음수 0.5 처리 차이).
- 9.9 의 `value-up`/`value-down` 은 위 2번에서 0 이 아닌 표시값에만 붙인다.
- null 값은 `-` 로 표시한다.
- 포매터 객체는 모듈 로드 시 한 번 만들어 재사용한다.

## 12. 외부 의존성

- MVP: 외부 라이브러리, CDN 스크립트, 웹 글꼴 스크립트 없음. `index.html` 에 외부 `<script>` 를 두지 않는다.
- 사용하는 브라우저 기능: ES 모듈, `localStorage`, `crypto.randomUUID`, `Intl.NumberFormat`(`minimumFractionDigits`, `maximumFractionDigits` 옵션만. 10절), `Blob`, `URL.createObjectURL`, `File.text()`. 지원 브라우저와 최소 버전은 docs/01_요구사항.md 6절 NFR-02 를 따른다. NFR-02 의 최소 버전에 없는 기능을 쓰려면 먼저 NFR-02 를 고친다.
- 개발 확인용 도구(앱 의존성 아님): Node 22 이상(계산 검증 스크립트 verify.mjs), Python 3 과 Python Playwright(화면 검증 스크립트 verify_ui.py, 정적 서버는 표준 라이브러리 http.server). `package.json` 은 만들지 않는다. 설치 명령은 docs/05_작업지시서.md 2.3 을 따른다.
- Chart.js 는 확장 작업에서만 도입하며 MVP 에서는 로드하지 않는다.

## 13. 확장 지점

확장 기능은 MVP 에서 구현하지 않는다. 작업 내용과 순서는 docs/05_작업지시서.md 의 확장 작업(E-xx)을 따른다. 아래는 모듈을 어디에 붙일지의 개요이며, 새 파일, 새 데이터 형식, 새 공식은 모두 제안 (구현 전 사용자 승인 필요) 이다. 승인되면 이 문서의 2, 3, 5, 7, 9절을 먼저 수정한 뒤 구현한다.

### 13.1 차트(자산 비중 원형, 종목별 수익률 막대)

- 제안 (구현 전 사용자 승인 필요): 새 화면 모듈 `js/charts.js`. DOM(canvas)과 Chart.js 를 다루는 화면 계층이다. `charts.js` 를 import 하는 모듈은 `main.js` 하나이고, `charts.js` 는 `portfolio.js` 의 상수만 import 한다(docs/05_작업지시서.md E-01).
- 입력: 기존 파생 데이터 `AllocationResult`, `HoldingRow[]` 를 그대로 쓴다. 새 계산 공식은 필요 없다.
- Chart.js 는 버전을 고정한 CDN 주소로 `index.html` 에서 로드한다. 구체 버전과 주소는 작업지시서에서 정한다.
- 연결: `main.render()` 에서 `ui.renderApp` 다음에 차트 갱신 함수를 호출한다.

### 13.2 해외 종목 달러 입력과 환율 환산

- 제안 (구현 전 사용자 승인 필요): 거래에 통화와 환율 필드를 추가하고 `version` 을 2 로 올린다. `storage.js` 에 버전 1 -> 2 변환 함수를 둔다.
- 원화 환산 공식은 docs/03_계산규칙.md 에 먼저 정의한다. 계산은 `portfolio.js` 에서 원화로 환산한 뒤 기존 흐름을 그대로 쓴다.
- `ui.js` 거래 입력 폼에 통화 선택과 환율 입력칸이 추가된다.

### 13.3 CSV 거래내역 일괄 등록

- 제안 (구현 전 사용자 승인 필요): 새 순수 모듈 `js/csv.js`. CSV 텍스트를 `TransactionInput[]` 로 바꾸는 일만 한다.
- 각 행은 `transactions.createTransaction` 으로 검사하고, 모두 통과하면 기존 거래와 합친 배열을 `validateTransactionList` 로 한 번에 검사한다. 하나라도 실패하면 아무것도 추가하지 않는다(행 번호를 붙인 오류).
- 화면: 데이터 관리 영역에 CSV 파일 선택 요소를 추가한다. CSV 열 형식은 작업지시서에서 제안한다.

### 13.4 적립식 투자 시뮬레이터

- 제안 (구현 전 사용자 승인 필요): 새 순수 모듈 `js/simulator.js` (월 투자금, 기간, 예상 수익률 -> 월별 결과 배열)와 새 화면 영역. 그래프는 13.1의 Chart.js 를 재사용한다.
- 복리 공식은 docs/03_계산규칙.md 에 먼저 정의한다.
- 포트폴리오 상태와 독립적이며, 입력값 저장 여부는 승인 시 정한다.
