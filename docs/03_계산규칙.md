## 2. 용어와 기호

### 2.1 기호

| 기호 | 용어 | 정의 |
|---|---|---|
| q | 거래 수량 | 거래의 quantity |
| p | 거래 가격 | 거래의 price (1주당 가격) |
| f | 수수료 | 거래의 fee (원) |
| Q | 보유수량 | 종목의 현재 보유수량 (5절) |
| A | 평균단가 | 종목의 이동평균 단가, 매수 수수료 포함 (4절) |
| R | 실현손익 | 종목별 누적 실현손익 (6절) |
| P | 현재가 | 평가에 쓰는 가격 (7.1절) |
| V | 평가금액 | Q x P |
| C | 취득원가 | Q x A |
| U | 평가손익 | V - C |
| r | 수익률 | U / C x 100 (단위 %) |
| V_k | 자산군 평가금액 | 자산군 k 에 속한 종목들의 V 합계 |
| T | 총평가금액 | 모든 종목의 V 합계 |
| w_k | 비중 | 자산군 k 의 비중 (단위 %) |
| t_k | 목표 비중 | 자산군 k 의 목표 비중 (단위 %) |
| D_k | 리밸런싱 금액 | 자산군 k 의 리밸런싱 금액 (원) |

- k 는 stock, bond, cash, other 중 하나이다. 화면 표시는 각각 주식, 채권, 현금, 기타이다.
- "취득원가"는 이 문서에서 Q x A 를 부르는 이름이다. 매수 수수료가 포함된 보유분의 원가이다.
- 공식의 곱셈은 "x", 나눗셈은 "/" 로 쓴다.

### 2.2 종목의 식별

- 종목은 거래의 name 으로 식별한다. name 은 앞뒤 공백을 제거한 문자열이며, 제거 후 문자열이 완전히 같으면 같은 종목이다.
- 종목의 자산군은 그 종목의 거래가 가진 assetClass 이다. 같은 종목의 거래는 모두 같은 assetClass 를 가진다(9.3절).

## 3. 거래 처리 순서

### 3.1 정렬 규칙

- 모든 계산은 전체 거래 배열을 처음부터 다시 처리해서 얻는다. 이전 계산 결과를 이어서 갱신하지 않는다.
- 처리 순서는 date 오름차순이다. date 가 같으면 거래 배열에서 앞에 있는 거래를 먼저 처리한다.
- date 는 "YYYY-MM-DD" 문자열이므로 문자열 비교로 정렬한다. 같은 date 의 순서를 유지하도록 안정 정렬(Array.prototype.sort 는 ES2019 이후 안정 정렬이다)을 쓴다.
- 새 거래는 배열 끝에 추가한다. 따라서 같은 date 안에서는 나중에 입력한 거래가 나중에 처리된다.

### 3.2 처리 절차

모든 종목의 상태를 Q = 0, A = 0, R = 0 으로 시작해 3.1절 순서대로 거래를 하나씩 적용한다.

```
매수(type "buy"):
  A = (Q x A + q x p + f) / (Q + q)
  Q = Q + q
매도(type "sell"):
  q > Q 이면 처리를 멈추고 실패를 반환한다 (9절)
  R = R + (p - A) x q - f
  Q = Q - q
  Q 가 0 이면 A = 0
```

- 매도에서 R 을 갱신할 때의 A 는 그 매도 직전의 평균단가이다. 따라서 R 갱신은 Q 감소와 A 초기화보다 먼저 한다.

## 4. 평균단가

### 4.1 공식

평균단가는 이동평균법으로 계산하며 매수할 때만 갱신한다. 매수 수수료는 취득원가에 포함한다.

```
새 평균단가 = (기존 보유수량 x 기존 평균단가 + 매수수량 x 매수가 + 수수료) / (기존 보유수량 + 매수수량)
```

- 매도는 평균단가를 바꾸지 않는다. 단, 매도 후 보유수량이 0 이면 평균단가를 0 으로 초기화한다(8절).
- 보유수량이 0 인 상태에서 매수하면 공식의 첫 항이 0 이므로 새 평균단가 = (q x p + f) / q 이다.

### 4.2 예시 (수수료 포함)

| 순서 | 거래 | 계산 | 보유수량 | 평균단가 |
|---|---|---|---|---|
| 1 | 10주 5,000원 매수, 수수료 500원 | (0 + 50,000 + 500) / 10 | 10 | 5,050 |
| 2 | 20주 5,600원 매수, 수수료 1,000원 | (50,500 + 112,000 + 1,000) / 30 | 30 | 5,450 |

이 예시는 14절 C-02 와 같다.

## 5. 보유수량

- 보유수량은 종목별로 매수 수량의 합계에서 매도 수량의 합계를 뺀 값이며, 3.2절 절차로 얻는다.
- 처리 도중 어느 시점에서도 보유수량은 0 보다 작아질 수 없다. 이를 어기는 거래 배열은 허용하지 않는다(9절).
- 거래 수량이 양의 정수이므로 보유수량은 항상 0 이상의 정수이다.

## 6. 실현손익

### 6.1 공식

```
실현손익 = (매도가 - 평균단가) x 매도수량 - 매도 수수료
```

- 실현손익은 매도할 때만 생기며 종목별로 누적한다. 보유수량이 0 이 되어도 누적값은 유지한다.
- 매도 수수료가 크거나 매도가가 평균단가보다 낮으면 실현손익은 음수가 될 수 있다.

### 6.2 예시 (매도 수수료 포함)

평균단가 8,000원, 보유수량 20주에서 시작한다.

| 순서 | 거래 | 계산 | 이번 실현손익 | 누적 실현손익 | 보유수량 |
|---|---|---|---|---|---|
| 1 | 8주 9,500원 매도, 수수료 1,200원 | (9,500 - 8,000) x 8 - 1,200 | 10,800 | 10,800 | 12 |
| 2 | 2주 7,000원 매도, 수수료 300원 | (7,000 - 8,000) x 2 - 300 | -2,300 | 8,500 | 10 |

평균단가는 두 매도 후에도 8,000원이다. 이 예시는 14절 C-03 과 같다.

## 7. 평가금액, 평가손익, 수익률

### 7.1 평가에 쓰는 현재가 P

아래 표를 위에서부터 확인해 처음 맞는 경우를 적용한다.

| 경우 | P |
|---|---|
| 종목명이 "현금" | 1 (12절) |
| 현재가 객체에 그 종목명 키가 있음 | 입력된 현재가 |
| 현재가 객체에 그 종목명 키가 없음 (현재가 미입력) | A (평균단가) |

- 현재가 미입력 종목은 "현재가 미입력" 표시 대상이다. 표시 대상 여부는 Q > 0 이고 종목명이 "현금"이 아니며 현재가 키가 없을 때 참이다.
- 리밸런싱(11절)과 자산군 비중(10절)도 같은 P 로 계산한 평가금액을 쓴다.

### 7.2 공식

```
평가금액 V = Q x P
취득원가 C = Q x A
평가손익 U = V - C
수익률   r = U / C x 100     (Q > 0 일 때만)
```

- 현재가 미입력이면 P = A 이므로 U = 0, r = 0 이다.
- Q = 0 이면 V = 0, U = 0 이고 r 은 계산하지 않는다(값 없음, 계산 결과는 null). 화면에는 평가 관련 칸을 `-` 로 표시한다(docs/02_설계문서.md 6.2).
- Q > 0 이면 A > 0 이므로 C > 0 이고, r 의 분모는 0 이 되지 않는다.

## 8. 전량 매도 후 재매수

- 매도로 Q 가 0 이 되면 A 를 0 으로 초기화한다. R 은 유지한다.
- 이후 재매수의 평균단가는 4.1절 공식에서 기존 보유수량이 0 이므로 이전 보유 기간의 평균단가와 섞이지 않는다.
- 재매수 후의 매도는 새 평균단가로 실현손익을 계산하고, 이전 기간의 R 에 더한다.
- 예시는 14절 C-04 이다.

## 9. 거래 추가와 삭제 검증

### 9.1 초과 매도 검증

- 매도 시점의 보유수량보다 많이 매도하는 거래는 허용하지 않는다.
- 검증은 변경 후의 전체 거래 배열을 3절 절차로 처음부터 다시 처리해서 한다. 처리 중 한 번이라도 q > Q 인 매도가 나오면 실패이다.
- 실패하면 변경(추가 또는 삭제)을 적용하지 않고 오류를 보여준다. 거래 배열, 저장 데이터, 화면 상태는 변경 전과 같다.
- 실패의 원인이 되는 거래는 추가한 거래가 아닐 수 있다. 과거 날짜 거래를 추가하면 그보다 뒤 날짜의 기존 매도가 실패할 수 있다. 오류에는 실패한 매도 거래를 알 수 있는 정보를 담는다(메시지는 docs/01_요구사항.md 5.2 의 VE-09~VE-11, 오류 구조는 docs/02_설계문서.md 7.1, 7.2).

### 9.2 검증이 필요한 변경

| 변경 | 초과 매도 가능성 | 처리 |
|---|---|---|
| 매도 거래 추가 | 있음 | 전체 재계산으로 검증 |
| 매수 거래 추가 | 없음 (보유수량이 늘기만 한다) | 전체 재계산으로 검증 (같은 함수를 쓴다) |
| 매수 거래 삭제 | 있음 | 전체 재계산으로 검증 |
| 매도 거래 삭제 | 없음 (보유수량이 늘기만 한다) | 전체 재계산으로 검증 (같은 함수를 쓴다) |

모든 변경에 같은 재계산 검증을 적용한다. 경우를 나눈 별도 코드를 만들지 않는다.

### 9.3 자산군 일치 검증

- 거래를 추가할 때, 같은 종목명의 기존 거래가 있고 그 assetClass 가 새 거래의 assetClass 와 다르면 추가하지 않고 오류를 보여준다. 매수와 매도 모두 적용한다.
- 종목명 비교는 앞뒤 공백 제거 후의 문자열로 한다(2.2절).
- 거래 추가 시 검사 순서: 데이터 형식 검사(docs/02_설계문서.md 5.1) -> 자산군 일치 검사 -> 초과 매도 검사. 메시지 단위의 순서는 docs/01_요구사항.md 5.1 이다.

## 10. 자산군 비중

```
V_k = 자산군 k 에 속한 모든 종목의 V 합계
T   = V_stock + V_bond + V_cash + V_other
w_k = V_k / T x 100
```

- 보유수량 0 인 종목은 V = 0 이므로 합계에 영향이 없다.
- 현재가 미입력 종목은 7.1절의 P = A 로 평가한 V 를 합산한다.
- T = 0 이면 비중을 계산하지 않고 안내만 한다(안내 문구는 docs/01_요구사항.md 5.5 IN-03). Q 는 0 이상이고 P 는 0 보다 크므로 T 는 음수가 될 수 없다.
- 4개 자산군을 모두 계산한다. 보유 종목이 없는 자산군은 V_k = 0, w_k = 0 이다.
- 화면에 표시한 비중의 합은 반올림 때문에 100.00 이 아닐 수 있으며 보정하지 않는다.

## 11. 리밸런싱

### 11.1 계산 조건

다음 두 조건을 모두 만족할 때만 계산한다. 하나라도 어긋나면 계산하지 않고 안내만 한다.

1. T > 0
2. 목표 비중 합계 = 100

- 목표 비중은 4개 자산군 모두 키를 가지며 값은 소수 첫째 자리까지이다.
- 합계 판정은 부동소수점 오차를 피하기 위해 각 목표 비중을 10배 해 반올림한 정수의 합이 1000 인지로 한다. 예: 0.1 + 0.2 + 84.1 + 15.6 은 부동소수점 덧셈으로 99.99999999999999 이지만 1 + 2 + 841 + 156 = 1000 이므로 합계 100 으로 판정한다(14절 R-03).
- 결과는 자산군별 금액만 낸다. 종목별 배분이나 주수는 계산하지 않는다.

### 11.2 공식

```
D_k = T x t_k / 100 - V_k
```

- 곱셈을 먼저 하고 100 으로 나눈다(T x t_k / 100).
- 4개 자산군의 D_k 합계는 수학적으로 0 이다(목표 합계 100 이므로).

### 11.3 판정 규칙

판정은 D_k 를 원 단위로 반올림한 값 d_k 로 한다(반올림 방식은 13.1절).

| d_k | 판정 | 표시 금액 |
|---|---|---|
| 0 보다 큼 | 매수 | d_k |
| 0 보다 작음 | 매도 | d_k 의 절댓값 |
| 0 | 유지 | 0 |

- 내부값 D_k 가 0 이 아니어도 d_k 가 0 이면 "유지"이다. 예: D_k = 0.333 -> 유지, D_k = -0.666 -> 매도 1원(14절 R-04).
- 반올림 결과가 -0 이면 0 으로 본다.
- 판정과 표시 금액을 화면에 배치하는 형식은 docs/02_설계문서.md, docs/04_디자인가이드.md 를 따른다.

## 12. 현금 처리

- 현금은 종목명 "현금", 자산군 cash 인 거래로 입력한다. 수량 = 금액(원), 가격 = 1 이다.
- 종목명 "현금" 거래는 자산군 cash, 가격 1 이어야 한다. 어기면 거래를 추가하지 않는다(메시지 docs/01_요구사항.md 5.2 VE-08). 수수료는 다른 거래와 같은 조건(0 이상)만 적용하고 0 으로 강제하지 않는다.
- 현금 종목의 현재가는 1 로 고정한다. 현재가 객체에 "현금" 키가 있어도 쓰지 않는다. 현금 종목은 "현재가 미입력" 표시 대상이 아니다.
- 현금도 3절부터 7절의 공식을 그대로 적용한다. 가격 1, 수수료 0 으로 입력하면 A = 1, U = 0, r = 0 이다.
- 수수료가 있는 현금 매수(입금)는 4.1절 공식에 따라 수수료가 취득원가에 들어가 A 가 1 보다 커진다. P 는 1 로 고정이므로 U = Q x (1 - A) 는 음수가 되고 r 도 음수가 된다. 이는 입금에 든 비용이 원가에 반영된 결과이며 보정하지 않는다. 예시는 14절 C-15 이다. 수수료가 있는 현금 매도(출금)는 6.1절 공식에 따라 실현손익을 수수료만큼 줄인다.
- 현금 매수는 현금 보유가 늘어난 것, 현금 매도는 줄어든 것으로 본다. 보유 현금보다 많은 현금 매도는 9.1절에 따라 거부한다.
- 자산군 cash 에 "현금" 외 종목명(예: MMF, CMA)도 쓸 수 있다. 이런 종목은 일반 종목과 같이 현재가를 입력받아 평가하고 현재가 미입력 규칙(7.1절)을 적용한다. 가격 1 강제와 현재가 1 고정은 종목명 "현금" 에만 적용한다.
- 다른 종목의 매수나 매도는 현금 종목을 자동으로 바꾸지 않는다. 이 연동은 확정 규칙에 없다.

## 13. 반올림과 표시 규칙

### 13.1 반올림

- 내부 계산과 저장값은 반올림하지 않는다. 평균단가도 반올림하지 않은 값으로 다음 계산에 쓴다(14절 C-12 가 이를 확인한다).
- 반올림은 화면 표시 직전에 한 번만 한다.
- 반올림 방식은 절댓값 기준 "0 에서 먼 쪽" 이다. 0.5 경계는 절댓값이 커지는 쪽으로 반올림한다(예: 2.5 -> 3, -2.5 -> -3). Intl.NumberFormat 의 기본 반올림 방식(halfExpand)과 같고, Math.round(-2.5 -> -2)와는 다르다. 구현 방법은 docs/02_설계문서.md 10절이다. 14절 검증 사례는 0.5 경계에 걸리는 값이 없도록 만들었다.
- 반올림 결과가 0 이면 부호 없이 0 으로 표시한다("-0" 금지).

### 13.2 표시 자릿수

| 대상 | 표시 단위 |
|---|---|
| 평가금액, 평가손익, 실현손익, 총평가금액, 자산군 평가금액, 목표 금액, 리밸런싱 금액 | 원 단위 (소수 첫째 자리에서 반올림) |
| 평균단가 | 소수 둘째 자리 고정 (셋째 자리에서 반올림. 정수도 11,000.00 처럼 두 자리 표시) |
| 수익률, 비중 | 소수 둘째 자리 고정 (셋째 자리에서 반올림. 예: 10.00) |
| 현재가, 거래 가격, 수수료 | 최대 소수 둘째 자리 (셋째 자리에서 반올림하고 끝자리 0 은 생략. 예: 13000 -> 13,000, 152.5 -> 152.5, 0.125 -> 0.13) |
| 보유수량, 거래 수량 | 정수 그대로 |
| 목표 비중 합계 | 소수 첫째 자리 고정 (예: 100.0, 95.0) |
| 리밸런싱 결과 표의 목표 비중 | 소수 첫째 자리 고정 (예: 60.0, 35.5. docs/05_작업지시서.md 3.1 M-35) |
| 목표 비중 입력값 | 입력칸 안의 입력값 그대로 (소수 첫째 자리까지) |

- 천 단위 쉼표, 우측 정렬, 고정폭 숫자, 단위(% 와 원) 표기, 수익과 손실의 색은 docs/04_디자인가이드.md 를 따른다.
- 수익과 손실의 색 판정은 표시 반올림값의 부호로 한다. 표시값이 0 이면 수익도 손실도 아니다.

## 14. 검증 사례

### 14.1 사례 작성 규칙

- C-번호는 종목 계산(평균단가, 보유수량, 실현손익, 평가, 거래 검증) 사례, R-번호는 비중과 리밸런싱 사례이다. 번호는 다시 쓰지 않고 새 사례는 다음 번호를 붙인다.
- 각 사례는 서로 독립이다. 빈 상태(거래 없음, 현재가 없음)에서 시작한다.
- 입력 거래 표의 열은 거래 데이터 필드 이름과 같고 값도 저장 형식 그대로이다(assetClass 는 stock/bond/cash/other, type 은 buy/sell). # 열은 거래 배열의 인덱스이다. id 는 생략한다.
- 현재가는 JSON 객체로 적는다. {} 는 모든 종목이 현재가 미입력이라는 뜻이다.
- 기대값 표의 숫자는 반올림하지 않은 내부값이다. 정수와 유한소수는 그대로, 무한소수는 "분자/분모" 분수로 적는다. 표의 숫자에는 천 단위 쉼표를 쓰지 않는다.
- 표시값 표의 숫자는 13절 규칙으로 반올림한 값이다.
- 검증 스크립트는 내부값을 절대 오차 0.000001 이하이면 같다고 보고, 표시값은 정확히 일치해야 통과로 본다.
- "현재가 미입력" 열은 7.1절 표시 대상 여부이다(예/아니오). 수익률 null 은 계산하지 않음을 뜻한다.

### 14.16 R-01 사용자 예시: 리밸런싱

사용자가 제시한 예시이다. 총평가금액 10,000,000원, 주식 7,000,000원(목표 60%), 채권 2,000,000원(목표 30%), 현금 1,000,000원(목표 10%)이면 주식 1,000,000원 매도, 채권 1,000,000원 매수, 현금 유지이다. 기타는 목표 0%, 평가금액 0원이다.

### 14.17 R-02 목표 비중 합계가 100 이 아님

### 14.22 C-15 현금 매수 수수료로 생기는 음수 평가손익

현재가: {}
