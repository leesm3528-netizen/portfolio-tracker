## 1. 문서 범위와 우선순위

### 1.1 이 문서가 정하는 것

- 시각 규칙: 색상, 글꼴, 글자 크기, 간격, 테두리, 레이아웃 너비, 반응형 기준점
- 표시 형식: 숫자의 쉼표, 정렬, 부호, 단위, 색
- 컴포넌트 모양과 상태, 화면 영역의 시각적 순서
- 화면 문구의 문체와 머리말 규칙(13.1), 버튼 이름(13.3). 메시지 문구 자체의 원본은 docs/01_요구사항.md 5절이다

- 데이터 형식, 모듈 구조, 함수 이름, DOM 요소 id: docs/02_설계문서.md 가 원본이다.
- 기능 범위(MVP와 확장 구분): docs/01_요구사항.md 가 원본이다.

이 문서의 예시 숫자가 docs/03_계산규칙.md 와 다르면 03을 따르고 이 문서를 고친다.

### 1.3 적용 대상 파일

- css/style.css: 4절~7절의 CSS 변수 정의와 10절~11절의 컴포넌트 스타일

## 2. 디자인 원칙

1. 데이터 중심: 화면의 주인공은 숫자와 표다. 장식 요소로 숫자의 자리를 빼앗지 않는다.
2. 차분한 업무용 도구: 회계 장부나 증권사 잔고 화면처럼 무채색 바탕에 정보를 정렬한다. 색은 의미가 있을 때만 쓴다(강조, 수익, 손실, 오류, 경고, 포커스).
3. 장식 최소: 영역 구분은 여백과 1px 테두리로 한다. 그림자, 그라데이션, 장식 아이콘을 쓰지 않는다.
4. 정렬 우선: 숫자는 오른쪽, 글자는 왼쪽으로 정렬하고 같은 종류의 값은 같은 형식으로 표시한다.
5. 정직한 문구: 기능을 있는 그대로 설명한다. 꾸미는 말을 쓰지 않는다.
6. 한 가지 강조색: 강조색은 주 버튼과 링크에만 쓴다.

## 3. 금지 요소

아래 요소는 css/style.css, index.html, js/ui.js 어디에도 넣지 않는다. 검토 시 하나라도 발견되면 제거한다.

| 번호 | 금지 요소 | 구체적 예 | 대신 쓰는 것 |
|---|---|---|---|
| 1 | 그라데이션 배경 | linear-gradient, radial-gradient, 보라에서 파랑으로 넘어가는 배경 | 단색 --color-bg, --color-surface |
| 2 | 글래스모피즘 | backdrop-filter: blur, 반투명 흰 카드, 배경 흐림 | 불투명 단색 표면 |
| 3 | 큰 히어로 문구 | 화면 상단의 큰 제목과 소개 문장, 배경 이미지 | 앱 이름 한 줄(--font-size-xl) |
| 4 | 의미 없는 아이콘 | 이모지, 아이콘 글꼴, 장식용 SVG, 제목 앞 그림 기호 | 글자 라벨 |
| 5 | 둥근 알약 버튼 남발 | border-radius 999px 이나 50% 의 버튼, 태그 | --radius-sm 또는 --radius-md |
| 6 | 과한 그림자 | box-shadow 를 쓴 카드, 떠 있는 버튼 | 1px 테두리 --color-border |
| 7 | 과장 카피 | "스마트한 투자", "한눈에 쏙", "똑똑한", "완벽한", "AI가 분석한" | 13절의 기준 문구 |
| 8 | 의미 없는 애니메이션 | 숫자 카운트업, 페이드인, 흔들림, 로딩 스피너 장식 | 즉시 표시 |
| 9 | 장식 색 남발 | 영역마다 다른 배경색, 자산군마다 색 띠 | 무채색 표면과 테두리 |
| 10 | 웹 글꼴 추가 로드 | Google Fonts 등 외부 글꼴 link | 6.1의 시스템 글꼴 스택 |

box-shadow 는 사용하지 않는다. 포커스 표시는 outline 으로 한다(11.2 참고). 그래서 --shadow-* 변수는 두지 않는다.

## 4. CSS 변수 규칙

### 4.1 이름 접두어

| 접두어 | 용도 | 예 |
|---|---|---|
| --color-* | 색상 | --color-text, --color-profit |
| --font-* | 글꼴 종류, 크기, 굵기 | --font-family-base, --font-size-md, --font-weight-bold |
| --line-height-* | 줄 높이 | --line-height-base |
| --space-* | 여백과 간격 | --space-4 |
| --radius-* | 모서리 반경 | --radius-sm |
| --border-* | 테두리 두께 | --border-width |
| --layout-* | 레이아웃 너비와 바깥 여백 | --layout-max-width |
| --control-* | 입력칸과 버튼의 공통 치수 | --control-height |
| --focus-* | 포커스 표시 치수 | --focus-offset |

이름은 소문자와 하이픈만 쓴다. 이름은 역할로 짓는다(--color-profit 은 맞고 --color-red 는 틀리다).

### 4.2 사용 규칙

- 모든 변수는 css/style.css 맨 위의 :root 한 곳에 정의한다.
- 색상, 글꼴, 글자 크기, 줄 높이, 간격, 반경, 테두리 두께 값은 변수로만 쓴다. 규칙 본문에 #hex, px 숫자를 직접 쓰지 않는다.
- 예외 1: 반응형 기준점은 CSS 변수를 미디어 쿼리에 쓸 수 없으므로 7.5의 숫자를 미디어 쿼리에 직접 쓴다.
- 예외 2: 0, 100%, auto, 단위 없는 비율값(예: flex: 1)처럼 단위 체계와 무관한 값은 직접 쓴다.
- 이 문서에 없는 변수가 필요하면 먼저 이 문서 4절~7절에 추가한 뒤 CSS 에 쓴다.
- js/ui.js 는 색을 style 속성으로 직접 넣지 않는다. 10.1 의 클래스 이름을 붙이고 색은 CSS 가 정한다.

## 5. 색상

### 5.1 색상 변수 목록

명암비는 WCAG 2.1 상대 휘도 공식으로 계산했다. AA 기준은 본문 글자 4.5:1 이상, 입력칸 테두리 같은 UI 구성 요소와 포커스 표시 3:1 이상이다. 배경색과 테두리처럼 글자가 아닌 색은 기준 대상이 아니므로 "해당 없음"으로 적는다.

| 변수 | hex | 용도 | 흰색(#FFFFFF) 대비 | --color-bg 대비 | AA 판정 |
|---|---|---|---|---|---|
| --color-bg | #F6F6F4 | 페이지 바탕 | 해당 없음 | 해당 없음 | 해당 없음 |
| --color-surface | #FFFFFF | 영역(표, 폼) 바탕 | 해당 없음 | 해당 없음 | 해당 없음 |
| --color-surface-subtle | #F0F0EE | 표 머리, 행 호버, 비활성 입력칸 바탕 | 해당 없음 | 해당 없음 | 해당 없음 |

### 5.2 색 선택 이유

- 강조색은 짙은 청록 단색 #1F5F52 하나다. 파랑은 손실 색과 겹치고 보라/파랑 계열은 금지 요소이므로 피했다. 그라데이션으로 쓰지 않는다.
- 수익 빨강 #C62828, 손실 파랑 #1558B0 은 한국 증권 화면의 관례를 따른다.
- 오류 #B42318 은 수익 빨강과 색상이 가깝다. 그래서 오류는 색만으로 표시하지 않고 항상 "오류: " 로 시작하는 문장(13.1)과 --color-error-bg 바탕 영역으로 표시한다. 수익 숫자에는 바탕색을 쓰지 않으므로 둘은 위치와 모양으로 구분된다.
- 포커스 링 #B54700(짙은 주황)은 강조색, 수익, 손실 색과 구분되도록 골랐다. 포커스 링은 outline-offset 으로 요소 바깥 바탕(흰색 또는 --color-bg) 위에 그려지므로 바탕 대비 5.02:1 이상이다.

### 5.3 다크 모드

MVP 는 밝은 화면 한 가지만 제공한다. :root 에 color-scheme: light 를 지정한다. 다크 모드는 01_요구사항의 기능 범위에 없으므로 만들지 않는다.

## 6. 글꼴과 글자

### 6.1 글꼴 선택: 시스템 한글 글꼴 스택

선택: 시스템 글꼴 스택. CDN 웹 글꼴은 쓰지 않는다.

이유:
- 외부 요청이 없어 GitHub Pages 에서 첫 화면이 바로 그려지고 네트워크가 끊겨도 모양이 같다.
- 버전 고정과 라이선스 관리가 필요 없다.
- 윈도우(맑은 고딕), macOS/iOS(Apple SD Gothic Neo), 안드로이드(Noto Sans CJK KR) 모두 한글 글꼴이 기본 설치되어 있다.
- 업무용 도구 느낌에 맞고 장식 요소가 없다.

| 변수 | 값 |
|---|---|
| --font-family-base | -apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Malgun Gothic", "맑은 고딕", "Noto Sans KR", "Noto Sans CJK KR", "Segoe UI", Roboto, sans-serif |
| --font-family-numeric | "Segoe UI", -apple-system, BlinkMacSystemFont, Roboto, "Apple SD Gothic Neo", "Malgun Gothic", "맑은 고딕", sans-serif |

--font-family-numeric 은 숫자 칸과 숫자 입력칸에만 쓴다. 맑은 고딕의 숫자는 폭이 고르지 않을 수 있으므로 tnum 기능을 지원하는 라틴 시스템 글꼴을 앞에 둔다. 한글("원", "현재가 미입력")은 뒤쪽 한글 글꼴로 대체되어 표시된다.

### 6.2 숫자 글꼴 설정

숫자 칸, 숫자 입력칸, 요약 숫자에 아래 세 속성을 함께 적용한다.

- font-family: var(--font-family-numeric)
- font-variant-numeric: tabular-nums
- font-feature-settings: "tnum" 1 (font-variant-numeric 을 지원하지 않는 환경 대비)

### 6.3 글자 크기 단계

| 변수 | 값 | 용도 |
|---|---|---|
| --font-size-xs | 12px | 고지 문구, 표 아래 보조 설명 |
| --font-size-sm | 14px | 표 본문, 표 머리, 도움말, 오류 메시지 |
| --font-size-md | 16px | 기본 본문, 입력칸, 선택칸, 버튼 |
| --font-size-lg | 18px | 영역 제목(h2) |
| --font-size-xl | 22px | 앱 이름(h1) |

입력칸은 16px 미만으로 하지 않는다(iOS 사파리가 16px 미만 입력칸에서 화면을 확대한다).

### 6.4 굵기와 줄 높이

| 변수 | 값 | 용도 |
|---|---|---|
| --font-weight-regular | 400 | 본문, 숫자 |
| --font-weight-bold | 600 | 제목, 표 머리, 합계 행, 주 버튼 |
| --line-height-tight | 1.25 | 제목, 표 칸, 버튼 |
| --line-height-base | 1.5 | 본문, 안내, 오류 문장 |

굵기는 위 두 가지만 쓴다. 기울임꼴과 밑줄 장식은 쓰지 않는다(링크 밑줄은 예외).

## 7. 간격, 테두리, 레이아웃

### 7.1 간격 단계 (4px 기준)

변수 번호는 4px 의 배수를 뜻한다.

| 변수 | 값 | 주 용도 |
|---|---|---|
| --space-1 | 4px | 라벨과 입력칸 사이, 숫자와 보조 표시 사이 |
| --space-2 | 8px | 버튼 사이, 표 칸 위아래 안쪽 여백 |
| --space-3 | 12px | 표 칸 좌우 안쪽 여백, 입력칸 좌우 안쪽 여백 |
| --space-4 | 16px | 폼 항목 사이, 모바일 바깥 여백, 영역 안쪽 여백(모바일) |
| --space-6 | 24px | 영역 안쪽 여백(데스크톱), 데스크톱 바깥 여백 |
| --space-8 | 32px | 영역과 영역 사이 |
| --space-12 | 48px | 마지막 영역과 고지 문구 영역 사이 |

### 7.2 테두리 반경

| 변수 | 값 | 용도 |
|---|---|---|
| --radius-sm | 2px | 입력칸, 선택칸, 버튼 |
| --radius-md | 4px | 영역(section) 테두리, 오류/경고 안내 상자 |

이 두 값 외의 반경은 쓰지 않는다. 표 칸에는 반경을 주지 않는다.

### 7.3 테두리 두께

| 변수 | 값 | 용도 |
|---|---|---|
| --border-width | 1px | 영역, 표 구분선, 입력칸, 보조 버튼 |
| --border-width-strong | 2px | 포커스 링 두께, 표 합계 행 위 구분선 |
| --focus-offset | 2px | 포커스 링과 요소 테두리 사이 간격(outline-offset) |

### 7.4 레이아웃과 컨트롤 치수

| 변수 | 값 | 용도 |
|---|---|---|
| --layout-max-width | 1120px | 본문 최대 너비, 가운데 정렬 |
| --layout-gutter | 16px | 화면 좌우 바깥 여백(기본, 모바일) |
| --layout-gutter-wide | 24px | 화면 좌우 바깥 여백(1024px 이상) |
| --control-height | 40px | 입력칸, 선택칸, 버튼 높이 |
| --control-height-sm | 32px | 표 안 버튼 높이 |
| --control-width-sm | 112px | 표 안 입력칸(보유 현황 현재가) 너비 |

입력칸과 표 밖 버튼의 높이는 --control-height 40px 이상을 유지한다. 표 안 버튼만 행 높이를 줄이기 위해 --control-height-sm 을 쓴다.

### 7.5 반응형 기준점

CSS 변수로 만들 수 없으므로 아래 숫자를 미디어 쿼리에 그대로 쓴다. 기준점은 이 두 개만 쓴다.

| 이름 | 조건 | 적용 |
|---|---|---|
| 기본(모바일) | 640px 미만 | 한 열 배치, 폼 항목 한 줄에 하나 |
| 중간 | min-width: 640px | 거래 입력 폼 항목 두 열 |
| 넓음 | min-width: 1024px | 거래 입력 폼 한 줄 배치, 자산 비중과 리밸런싱 나란히 배치, --layout-gutter-wide 적용 |

지원 너비 범위(최소 360px)는 docs/01_요구사항.md 6절 NFR-05 를 따른다. 페이지 전체에 가로 스크롤이 생기면 안 된다. 넓은 표는 표를 감싼 요소 안에서만 가로 스크롤한다(10.1 참고).

## 8. 숫자 표시 규칙

반올림 기준과 자릿수는 docs/03_계산규칙.md 의 반올림 규칙이 원본이다. 이 절은 반올림된 값을 화면에 어떻게 쓰는지만 정한다. 표시 형식 함수는 js/ui.js 에 둔다(js/portfolio.js, js/rebalance.js 는 반올림하지 않은 숫자를 돌려준다).

### 8.1 공통

- 천 단위 쉼표를 넣는다. Intl.NumberFormat("ko-KR") 또는 Number.prototype.toLocaleString("ko-KR") 로 만든다.
- 숫자 칸은 오른쪽 정렬, 글자 칸(날짜, 종목명, 자산군, 구분)은 왼쪽 정렬한다. 표 머리도 해당 열과 같은 방향으로 정렬한다.
- 6.2 의 숫자 글꼴 설정을 적용한다.

### 8.2 값 종류별 형식

값 종류별 소수 자릿수와 반올림의 원본은 docs/03_계산규칙.md 13.2, 13.1 이고 구현 함수는 docs/02_설계문서.md 10절이다. 아래 표는 화면에 보이는 모양의 예다.

| 값 | 예 | 비고 |
|---|---|---|
| 금액(평가금액, 평가손익, 실현손익, 총평가금액, 자산군 평가금액, 목표 금액, 리밸런싱 금액) | 1,000,000 | 원 단위 |
| 평균단가 | 11,000.00 / 10,166.67 | 소수 두 자리 고정 |
| 현재가, 거래 가격, 수수료 | 13,000 / 152.5 / 0.13 | 최대 소수 두 자리, 끝자리 0 생략 |
| 수량, 보유수량 | 1,500 | 정수 |
| 수익률, 비중(표 안) | 12.34 / 5.00 | 소수 두 자리 고정, % 없음(8.3) |
| 목표 비중 합계 | 100.0% / 95.0% | 소수 한 자리 고정, % 붙임(표 밖) |
| 목표 비중(리밸런싱 결과 표 안) | 60.0 / 35.5 | 소수 한 자리 고정, % 없음(8.3) |
| 목표 비중 입력값 | 60 / 33.3 | 입력칸 안 입력값 그대로 |
| 날짜 | 2026-10-21 | 저장 형식 그대로 |

### 8.3 단위 표기

단위(% 와 원) 표기 규칙의 원본은 이 절이다.

- 표 안 숫자 칸에는 단위를 붙이지 않고 열 머리에 괄호로 적는다. 예: "평가금액(원)", "수익률(%)", "비중(%)". 수익률과 비중 칸에도 "%" 를 붙이지 않는다.
- 표 밖에 단독으로 나오는 금액(합계 문장, 안내 문장)은 숫자 뒤에 공백 없이 "원"을 붙인다. 예: "총평가금액 10,000,000원".
- 표 밖의 비율(목표 비중 합계 `#target-sum`, 안내 문장 안의 합계)은 숫자 뒤에 공백 없이 "%" 를 붙인다. 예: "100.0%".
- "만원", "억" 같은 축약 단위는 쓰지 않는다.

### 8.4 부호

| 대상 | 양수 | 음수 | 0 |
|---|---|---|---|
| 평가손익, 실현손익, 수익률 | "+" 를 붙인다. 예: +10,000 | "-" 를 붙인다. 예: -5,000 | 부호 없음. 예: 0, 0.00 |
| 그 밖의 금액, 수량, 가격, 비중 | 부호 없음 | 발생하지 않음 | 부호 없음 |
| 리밸런싱 금액 | 부호 없이 절댓값 표시, 구분 칸에 "매수" | 부호 없이 절댓값 표시, 구분 칸에 "매도" | "0", 구분 칸에 "유지" |

- 부호와 색은 반올림해 표시할 값으로 판단한다. 예를 들어 평가손익 -0.4 는 표시값이 0 이므로 "0" 으로 쓰고 부호와 색을 넣지 않는다. "-0" 은 절대 표시하지 않는다.
- 음수 부호는 ASCII 하이픈 "-" 를 쓴다. 괄호 표기 (5,000) 는 쓰지 않는다.
- 리밸런싱 "유지" 판단(표시 기준 0원)은 docs/03_계산규칙.md 를 따른다.

### 8.5 색만으로 구분하지 않는다

수익과 손실은 색과 함께 반드시 "+"/"-" 부호로도 구분된다. 리밸런싱의 매수/매도는 색을 쓰지 않고 "매수"/"매도"/"유지" 글자로 구분한다. 색을 볼 수 없는 사용자도 같은 정보를 얻어야 한다.

## 9. 수익과 손실 색 적용 대상

### 9.1 색을 적용하는 값

| 영역 | 값 | 양수 | 음수 | 0 |
|---|---|---|---|---|
| 보유 현황 표 | 평가손익 | --color-profit | --color-loss | --color-text |
| 보유 현황 표 | 수익률 | --color-profit | --color-loss | --color-text |
| 보유 현황 표 | 실현손익 | --color-profit | --color-loss | --color-text |

색은 글자색에만 적용한다. 칸 바탕색, 행 바탕색, 굵기는 바꾸지 않는다.

### 9.2 색을 적용하지 않는 값

- 평가금액, 현재가, 평균단가, 보유수량, 총평가금액
- 자산 비중 표의 모든 값
- 리밸런싱 표의 모든 값(매수/매도 구분 포함). 빨강/파랑이 수익/손실로 오해되지 않도록 한다.
- 거래 내역 표의 "매수"/"매도" 표시

### 9.3 클래스 이름

js/ui.js 는 표시값의 부호에 따라 숫자 칸에 아래 클래스 중 하나만 붙인다.

| 클래스 | 조건 | CSS |
|---|---|---|
| value-up | 표시값이 0보다 큼 | color: var(--color-profit) |
| value-down | 표시값이 0보다 작음 | color: var(--color-loss) |
| (없음) | 표시값이 0 | 기본 --color-text |

클래스 이름의 원본은 docs/02_설계문서.md 9.9 다.

## 10. 컴포넌트 규칙

### 10.1 표

- 바탕 --color-surface, 바깥 테두리 --border-width 실선 --color-border, 행 사이 아래쪽 구분선 --color-border. 세로 구분선은 쓰지 않는다.
- 칸 안쪽 여백: 위아래 --space-2, 좌우 --space-3. 글자 --font-size-sm, 줄 높이 --line-height-tight.
- tbody 칸은 줄바꿈하지 않는다(날짜 "2026-01-02" 가 하이픈에서 끊기지 않게). 넓이가 모자라면 아래 table-wrap 안에서 가로 스크롤한다. 행 머리(tbody 의 th scope="row")는 보통 굵기(--font-weight-regular)로 두어 합계 행의 굵은 글자와 구분한다(M-34).
- 줄무늬(zebra) 배경은 쓰지 않는다. 행 호버 시 바탕 --color-surface-subtle.
- 표는 div.table-wrap 으로 감싸고 overflow-x: auto 를 준다. 화면이 좁으면 이 안에서만 가로 스크롤한다.
- 모든 표에 caption 을 둔다(14.3 참고). caption 은 화면에 보이게 두고 영역 제목과 같은 내용이면 시각적으로 숨김 클래스(visually-hidden)를 쓴다.
- 합계 행이 있는 표(자산 비중)는 합계 행을 tfoot 에 두고 위쪽 구분선 --border-width-strong, 글자 --font-weight-bold 로 한다.

### 10.2 표 머리

- 바탕 --color-surface-subtle, 글자 --color-text-muted, --font-size-sm, --font-weight-bold.
- 단위는 괄호로 머리에 적는다(8.3 참고).
- 정렬은 열 내용과 같게 한다.
- 열 머리 줄바꿈을 막지 않는다. 좁은 화면에서 두 줄이 될 수 있다.

### 10.3 빈 상태 문구

데이터가 없을 때는 표를 숨기고 표 자리의 별도 p 요소(`#transactions-empty`, `#holdings-empty`, docs/02_설계문서.md 9.2, 9.3)에 문구를 표시한다. 글자 --color-text-muted, 가운데 정렬, 위아래 여백 --space-6. 그림이나 아이콘을 넣지 않는다. 문구는 docs/01_요구사항.md 5.5 의 IN-01, IN-02 다.

### 10.4 폼

- 각 입력 항목은 label 위, 입력칸 아래 순서로 세로 배치한다. label 과 입력칸 사이 --space-1, 항목 사이 --space-4.
- label 글자 --font-size-sm, --color-text, --font-weight-bold.
- 필수 표시는 별표 기호를 쓰지 않는다. 거래 입력 폼의 항목은 수수료를 빼고 모두 필수이므로 따로 표시하지 않고, 수수료 label "수수료(원)" 의 입력칸 아래에만 도움말 `#tx-fee-help`(IN-05)를 둔다. 수수료 입력칸은 처음과 거래 추가 후 모두 빈칸이다.
- 도움말은 --font-size-sm, --color-text-muted 로 표시하고 aria-describedby 로 입력칸과 연결한다. 목표 비중 입력칸 4개 아래에는 도움말 `#targets-help`(IN-06)를 하나 둔다.
- 자산군 선택칸의 첫 항목은 "선택하세요"(value 빈 문자열)이며 처음에 선택되어 있다(docs/02_설계문서.md 9.1).
- 거래 입력 폼 배치: 640px 미만 한 열, 640px 이상 두 열, 1024px 이상 한 줄(날짜, 종목명, 자산군, 구분, 수량, 가격, 수수료, 거래 추가 버튼 순서). 한 줄에 다 들어가지 않으면 줄바꿈한다.

### 10.5 입력칸

- 높이 --control-height, 좌우 안쪽 여백 --space-3, 글자 --font-size-md.
- 표 안 입력칸(보유 현황의 현재가)은 표 안 버튼(10.7)과 같이 높이 --control-height-sm, 글자 --font-size-sm, 너비 --control-width-sm 이다. 행 높이를 표 안 버튼이 있는 거래 내역 표와 맞추고 현재가 열이 다른 숫자 열보다 넓어지지 않게 하기 위해서다. 브라우저 기본 너비(width: auto)는 숫자 입력칸이 약 20 글자 폭이라 현재가 열이 다른 열의 두 배가 된다(docs/05_작업지시서.md 3.1 M-34, M-36).
- 테두리 --border-width 실선 --color-border-strong, 반경 --radius-sm, 바탕 --color-surface.
- 숫자 입력칸(수량, 가격, 수수료, 현재가, 목표 비중)은 type="number" 에 inputmode 를 함께 지정하고(수량은 numeric, 나머지는 decimal) 글자를 오른쪽 정렬하며 6.2 숫자 글꼴을 적용한다.
- 숫자 입력칸의 위아래 화살표(spin button)는 CSS 로 숨긴다.
- 날짜는 type="date" 를 쓴다.
- placeholder 를 label 대신 쓰지 않는다. placeholder 는 형식 예시에만 쓴다(예: 종목명 "예: 삼성전자").

### 10.6 선택칸

- select 요소를 쓴다. 치수와 테두리는 10.5 입력칸과 같다.
- 자산군 선택칸 항목 순서: 주식, 채권, 현금, 기타. 화면에는 한글만 보이고 value 는 docs/02_설계문서.md 의 값(stock, bond, cash, other)을 쓴다.
- 구분 선택칸 항목 순서: 매수, 매도.
- 브라우저 기본 화살표를 쓴다. 장식용 화살표 그림을 넣지 않는다.

### 10.7 버튼

| 종류 | 바탕 | 글자 | 테두리 | 쓰는 곳 |
|---|---|---|---|---|
| 주 버튼 | --color-accent | --color-on-accent, --font-weight-bold | 없음 | "거래 추가" 하나만 |
| 보조 버튼 | --color-surface | --color-text | --border-width 실선 --color-border-strong | "JSON 내보내기", "JSON 불러오기" |
| 표 안 버튼 | --color-surface | --color-text | --border-width 실선 --color-border-strong | 거래 내역의 "삭제" |

- 공통: 높이 --control-height(표 안 버튼은 --control-height-sm), 좌우 안쪽 여백 --space-4, 반경 --radius-sm, 글자 --font-size-md(표 안 버튼은 --font-size-sm).
- 한 화면에 주 버튼은 하나만 둔다.
- 버튼 글자는 동사형 짧은 이름이다(13.3 참고). 아이콘을 넣지 않는다.
- 버튼은 button 요소로 만들고 type 을 명시한다(폼 제출은 submit, 나머지는 button).
- "JSON 불러오기" 는 화면에 보이는 button 을 누르면 숨겨진 input type="file"(accept=".json,application/json")을 여는 방식으로 한다.

### 10.8 오류 메시지 위치

오류와 안내는 영역마다 하나인 메시지 줄(docs/02_설계문서.md 7.5 `MessageArea`, 9절 id)에 표시한다. 입력칸마다 따로 오류를 두지 않는다.

| 메시지 줄 | 위치 | 표시하는 것 |
|---|---|---|
| `#tx-message` | 거래 입력 폼 아래, 거래 추가 버튼 바로 아래 | 거래 입력 항목 오류, 자산군 불일치, 초과 매도 |
| `#transactions-message` | 거래 내역 표 바로 위 | 거래 삭제 불가 |
| `#holdings-message` | 보유 현황 표 바로 위 | 현재가 입력 오류 |
| `#targets-message` | 목표 비중 입력칸과 합계 아래 | 목표 비중 입력 오류 |
| `#data-message` | JSON 내보내기/불러오기 버튼 바로 아래 | 저장 실패, 저장 데이터 손상, 불러오기 오류와 완료 안내 |

- 오류 상자(`message-error`): 바탕 --color-error-bg, 왼쪽 테두리 --border-width-strong 실선 --color-error, 안쪽 여백 --space-3, 반경 --radius-md, 글자 --color-error, --font-size-sm, --line-height-base.
- 모든 오류 문장은 "오류: " 로 시작한다(13.1).
- 메시지 줄에는 aria-live="polite" 를 둔다(docs/01_요구사항.md NFR-04). 입력칸에 aria-invalid 와 오류용 aria-describedby 를 쓰지 않는다.
- 오류가 해결되거나 다음 동작이 성공하면 오류를 지운다. 오류는 자동으로 사라지게 하지 않는다(시간 제한 없음).
- 판정 조건은 docs/03_계산규칙.md, 문구는 docs/01_요구사항.md 5절을 따른다.

### 10.9 경고와 안내

- "현재가 미입력": 보유 현황 표의 현재가 칸에서 입력칸 아래에 --color-warning, --font-size-xs 글자로 표시한다. 바탕색은 넣지 않는다.
- 목표 비중 합계가 100 이 아님(VE-15), 총평가금액 0(VE-16, IN-03): 해당 영역 안 결과 표 자리(`#rebalance-message`, `#allocation-message`)에 경고 상자(`message-info`)로 표시한다. 경고 상자는 오류 상자와 같은 모양에 색만 --color-warning-bg, --color-warning 으로 바꾼다. "오류: " 머리말 대신 "안내: " 로 시작한다(13.1).

### 10.10 고지 문구 영역

- 화면 맨 아래 footer 요소에 한 문장을 둔다. 문구는 정확히 "계산 결과는 참고용이며 투자 판단의 책임은 본인에게 있습니다." 이다. 글자를 바꾸지 않는다.
- 위쪽 구분선 --border-width 실선 --color-border, 위아래 안쪽 여백 --space-4, 위쪽 바깥 여백 --space-12.
- 글자 --font-size-xs, --color-text-muted, 왼쪽 정렬.
- 숨기거나 접지 않는다. 모든 화면 너비에서 보여야 한다.

## 11. 상태

### 11.1 호버

| 요소 | 호버 시 |
|---|---|
| 주 버튼 | 바탕 --color-accent-hover |
| 보조 버튼, 표 안 버튼 | 바탕 --color-surface-subtle |
| 표 행(tbody tr) | 바탕 --color-surface-subtle |
| 링크 | 밑줄 유지, 색 --color-accent-hover |

호버에 이동, 확대, 그림자를 쓰지 않는다. 전환 효과(transition)를 쓰지 않는다.

### 11.2 포커스

- :focus-visible 에 outline: var(--border-width-strong) solid var(--color-focus); outline-offset: var(--focus-offset) 를 준다.
- outline: none 으로 포커스 표시를 지우지 않는다.
- 포커스 표시는 버튼, 입력칸, 선택칸, 링크, 파일 선택 버튼 모두 같다.

### 11.3 비활성

- 글자 --color-text-disabled, 바탕 --color-surface-subtle, 테두리 --color-border, cursor: not-allowed.
- disabled 속성으로 만든다. 투명도(opacity)로 흐리게 하지 않는다.
- 현금 종목의 현재가는 1 로 고정되므로 현재가 칸에 입력칸 대신 "1" 을 글자로 표시한다(비활성 입력칸으로 두지 않는다).

### 11.4 오류

- 오류는 영역 메시지 줄의 오류 상자로만 표시한다(10.8). 입력칸 테두리 색은 바꾸지 않는다.
- 색만으로 오류를 알리지 않는다. 반드시 "오류: " 로 시작하는 문장을 함께 표시한다.

## 12. 화면 배치

### 12.1 영역 순서

위에서 아래로 다음 순서다. 각 영역은 section 요소이며 h2 제목을 가진다(1번 머리글과 8번 고지는 제외). DOM id 와 모듈 연결은 docs/02_설계문서.md 를 따른다.

| 순서 | 영역 | h2 제목 | 내용 |
|---|---|---|---|
| 1 | 머리글(header) | 없음(h1 "포트폴리오 트래커") | 앱 이름 한 줄 |
| 2 | 거래 입력 | 거래 입력 | 거래 입력 폼, 거래 추가 판정 오류 |
| 3 | 보유 현황 | 보유 현황 | 종목별 표(현재가 입력칸 포함) |
| 4 | 자산 비중 | 자산 비중 | 자산군별 평가금액과 비중 표, 합계 행 |
| 5 | 리밸런싱 | 리밸런싱 | h3 "목표 비중" 아래 목표 비중 입력칸 4개와 합계 표시, h3 "리밸런싱 결과" 아래 결과 표(묶음 구조는 docs/02_설계문서.md 9.5) |
| 6 | 거래 내역 | 거래 내역 | 거래 표(처리 순서대로), 행마다 삭제 버튼 |
| 7 | 데이터 관리 | 데이터 관리 | JSON 내보내기, JSON 불러오기 버튼, 불러오기 오류 |
| 8 | 고지(footer) | 없음 | 고지 문구 한 문장 |

- 영역 사이 간격 --space-8. 영역은 --color-surface 바탕, --border-width 실선 --color-border, 반경 --radius-md, 안쪽 여백 --space-4(모바일) / --space-6(1024px 이상).
- 표의 열 순서와 열 이름의 원본은 docs/02_설계문서.md 9절이다. 이 문서는 열 머리의 단위 표기(8.3)만 정한다. 예: 02 9.3 의 "평가금액" 열 머리는 "평가금액(원)" 으로 쓴다. 리밸런싱 결과 표의 열도 02 9.6 을 따른다.

### 12.2 데스크톱 (1024px 이상)

- 본문 너비 최대 --layout-max-width, 가운데 정렬, 좌우 바깥 여백 --layout-gutter-wide.
- 거래 입력 폼은 한 줄 배치(10.4 참고).
- 4번 자산 비중(`#allocation-section`)과 5번 리밸런싱(`#rebalance-group`)은 두 열로 나란히 둔다(왼쪽 자산 비중, 오른쪽 리밸런싱, 열 사이 --space-6). 나머지 영역은 전체 너비 한 열이다.

### 12.3 모바일 (640px 미만)

- 모든 영역 한 열, 좌우 바깥 여백 --layout-gutter.
- 거래 입력 폼은 항목 한 줄에 하나, 거래 추가 버튼은 전체 너비.
- 표는 div.table-wrap 안에서 가로 스크롤한다. 표를 카드 목록으로 바꾸지 않는다(같은 데이터를 두 가지 마크업으로 그리는 중복을 피한다).
- 데이터 관리 버튼 두 개는 세로로 쌓고 각각 전체 너비.

640px 이상 1024px 미만은 모바일 배치에 거래 입력 폼만 두 열로 한다.

## 13. 문구 가이드

### 13.1 톤

이 절은 화면 문구 문체와 머리말 규칙의 원본이다. 문구 자체의 원본은 docs/01_요구사항.md 5절이다.

- 화면 문구는 존댓말 "~합니다/~하세요" 로 쓴다. "~해 주세요" 는 쓰지 않는다. 고지 문구("~있습니다.")와 문체를 맞춘다. (문서는 평서문, 화면 문구는 존댓말이다. 둘을 섞지 않는다.)
- 머리말: 메시지 줄의 오류는 "오류: ", 안내는 "안내: " 로 시작한다. js/ui.js 가 `showMessage` 의 kind("error", "info")에 따라 01 5절 문구 앞에 붙인다. index.html 의 정적 안내(01 5.5 IN-03)는 머리말을 문구에 포함해 적는다. 확인 대화상자(C-01, C-02), 빈 상태 문구(IN-01, IN-02), 도움말(IN-05, IN-06), "현재가 미입력" 표시, 고지 문구에는 머리말을 붙이지 않는다.
- 짧고 구체적으로 쓴다. 무엇이 잘못되었는지와 어떻게 고치는지를 함께 쓴다.
- 감탄, 과장, 의인화("제가 계산해 드릴게요"), 느낌표를 쓰지 않는다.
- 용어는 01_요구사항의 용어를 그대로 쓴다: 거래, 종목, 자산군, 보유수량, 평균단가, 현재가, 평가금액, 평가손익, 수익률, 실현손익, 목표 비중, 리밸런싱 금액, 총평가금액.

## 14. 접근성

### 14.1 label 연결

- 모든 입력칸과 선택칸은 label 의 for 와 입력칸 id 로 연결한다.
- 보유 현황 표 안의 현재가 입력칸처럼 화면에 label 이 따로 없는 입력칸은 aria-label 에 "{종목명} 현재가" 를 넣는다.
- 목표 비중 입력칸 4개는 각각 "주식 목표 비중(%)" 처럼 자산군 이름을 포함한 label 을 가진다.
- 도움말(`#tx-fee-help`, `#targets-help`)은 aria-describedby 로 입력칸과 연결한다. 오류 문장은 영역 메시지 줄의 aria-live 로 읽힌다(10.8).

### 14.2 키보드 조작

- 모든 기능은 마우스 없이 Tab, Shift+Tab, Enter, Space 로 쓸 수 있어야 한다.
- Tab 순서는 12.1 영역 순서와 화면에 보이는 순서와 같다. tabindex 에 양수를 쓰지 않는다.
- 거래 입력 폼은 form 요소로 만들어 마지막 입력칸에서 Enter 를 누르면 거래 추가가 실행되게 한다.
- 거래 삭제 후 포커스는 다음 행의 삭제 버튼으로, 다음 행이 없으면 거래 내역 영역 제목(`#transactions-heading`, tabindex="-1")으로 옮긴다. 구현 방식은 docs/02_설계문서.md 7.5 다.
- 보유 현황 표가 다시 그려져도 포커스가 있던 현재가 입력칸의 포커스를 유지한다(02 7.5).
- 거래 추가에 성공하면 종목명, 수량, 가격, 수수료를 비우고 포커스를 첫 입력칸(날짜)으로 옮긴다. 날짜 입력칸은 직전 입력 날짜를 유지한다(같은 날 여러 거래를 연속 입력하기 쉽다. docs/02_설계문서.md 7.5 `resetTransactionForm`).

### 14.3 표 caption 과 scope

- 모든 표에 caption 을 둔다. 예: "보유 현황", "자산군별 비중", "리밸런싱 결과", "거래 내역".
- 열 머리 th 에 scope="col" 을 준다.
- 각 행의 첫 칸(종목명 또는 자산군)은 th scope="row" 로 만든다. 거래 내역 표는 날짜 칸을 th scope="row" 로 한다.
- 합계 행의 "합계" 칸은 th scope="row" 로 만든다.
- 삭제 버튼에는 aria-label 로 대상 거래를 밝힌다. 예: "2026-10-21 삼성전자 매수 거래 삭제".

### 14.4 그 밖

- html 요소에 lang="ko" 를 준다.
- 화면 확대 200% 에서 내용이 잘리지 않아야 한다(글자 크기를 px 로 고정하되 레이아웃은 max-width 와 줄바꿈으로 대응한다).
- 5절 명암비 기준을 지키지 않는 새 색을 추가하지 않는다.
