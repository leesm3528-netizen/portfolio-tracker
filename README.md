# 포트폴리오 트래커 + 리밸런싱 계산기

개인 투자자가 매수/매도 거래를 기록하고, 종목별 평균단가와 수익률, 자산군 비중을 확인하며, 목표 비중에 맞추려면 자산군별로 얼마를 사고팔아야 하는지 계산하는 웹 앱이다. 원화 기준이며 현재가는 사용자가 직접 입력한다. 실시간 시세를 가져오지 않고, 서버 없이 브라우저에서만 동작한다.

## 상태

개발 중이다. 1단계(문서) 완료. 2단계(프로젝트 전용 스킬 4개) 완료. 3단계(파일구조 골격과 기본 화면: index.html, css/style.css) 완료. 4단계(MVP 구현) 진행 중이다. 계산 모듈부터 만들고 있어 화면은 아직 정적 뼈대만 보인다. 진행 상황은 HANDOFF.md 를 본다.

## 주요 기능 (MVP)

- 거래 입력: 날짜, 종목명, 자산군(주식/채권/현금/기타), 매수/매도, 수량, 가격, 수수료
- 보유 현황: 종목별 보유수량, 평균단가, 현재가(직접 입력), 평가금액, 평가손익, 수익률, 실현손익
- 자산 비중: 자산군별 평가금액과 비중
- 리밸런싱: 자산군별 목표 비중을 입력하면 자산군별 매수/매도 금액을 계산
- 저장: localStorage 자동 저장, JSON 내보내기/불러오기

계산 방식(이동평균법 평균단가, 수수료 처리, 리밸런싱 금액 등)은 docs/03_계산규칙.md 를 본다. 확장 기능(차트, 해외 종목과 환율, CSV 일괄 등록, 적립식 투자 시뮬레이터)은 아직 구현하지 않으며 계획은 docs/05_작업지시서.md 9절에 있다.

## 폴더 구조

```

  js/main.js            화면 연결, 이벤트 처리 (4단계)
  js/storage.js         저장/불러오기 (4단계)
  js/transactions.js    거래 추가/삭제 (4단계)
  js/portfolio.js       평균단가, 수익률 계산 (4단계)
  js/rebalance.js       리밸런싱 계산 (4단계)

```

모듈별 책임과 의존 방향은 docs/02_설계문서.md 2절, 3절을 본다.

## 로컬에서 확인하는 법

ES 모듈은 file:// 주소로 열리지 않으므로 확인할 때만 정적 파일 서버를 쓴다. 앱 기능은 서버에 의존하지 않는다.

```
cd portfolio-tracker
py -m http.server 8000
```

`py` 는 Windows 의 Python 런처다. 다른 환경에서는 `python3 -m http.server 8000` 을 쓴다.

브라우저에서 `http://localhost:8000/` 을 연다. 열 수 있는 주소와 이유는 docs/01_요구사항.md 6.2 를 본다.

계산 검증은 Node 22 이상에서 `node skills/calc-rule-verify/scripts/verify.mjs` 로, 화면 검증은 Python Playwright 로 `py skills/ui-verify/scripts/verify_ui.py` 로 한다(둘 다 2단계에서 작성. 준비 명령은 docs/05_작업지시서.md 2.3).

## 데이터 보존

데이터는 사용 중인 브라우저의 localStorage 에만 저장되고 외부로 전송되지 않는다. 브라우저 데이터 삭제나 기기 변경 시 사라질 수 있으므로 JSON 내보내기로 백업한다. 자세한 한계는 docs/01_요구사항.md 6.1 을 본다.

## 협업자와 다른 AI 작업자에게

이 프로젝트는 여러 작업자(사람, Claude Code, Codex, Copilot 등)가 이어서 작업한다. 이전 대화 기록은 남지 않으므로 다음 순서로 문서만 보고 이어간다.

1. HANDOFF.md 에서 현재 단계와 다음 할 작업 ID 를 확인한다.
2. AGENTS.md 의 규칙과 작업 절차를 따른다.
3. docs/05_작업지시서.md 에서 그 작업 항목을 찾아 수행한다.
