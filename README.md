# 포트폴리오 트래커

매수/매도 거래를 기록해 종목별 평균단가, 수익률, 실현손익과 자산군 비중을 보고, 목표 비중에 맞추기 위한 자산군별 매수/매도 금액을 계산하는 브라우저용 정적 웹 앱이다.

## 1. 상태

MVP 기능은 모두 구현되어 있고 README 사용법과 배포 방법을 작성했다. GitHub Pages 실제 배포는 사용자 승인 뒤 한다. 진행 상황은 HANDOFF.md 를 본다.

## 2. 기능

MVP 에서 하는 것(상세와 수용 기준은 docs/01_요구사항.md 3.1, 4절):

- 거래 입력: 날짜, 종목명, 자산군(주식/채권/현금/기타), 구분(매수/매도), 수량, 가격, 수수료
- 거래 내역 표시와 거래 삭제
- 보유 현황: 종목별 보유수량, 평균단가, 현재가(직접 입력), 평가금액, 평가손익, 수익률, 실현손익
- 자산 비중: 자산군별 평가금액과 비중, 총평가금액
- 목표 비중 입력과 자산군별 리밸런싱 금액 계산
- 브라우저 localStorage 자동 저장, JSON 내보내기와 불러오기

하지 않는 것(이유는 docs/01_요구사항.md 3.3):

- 실시간 시세 조회. 현재가는 사용자가 직접 입력한다.
- 로그인, 서버 저장, 기기 간 자동 동기화
- 세금 계산, 배당금과 이자 기록, 리밸런싱 주수 계산, 주문 실행
- 거래 수정. 잘못 입력한 거래는 삭제하고 다시 입력한다.
- 주식 매수/매도 때 현금 잔고 자동 증감. 현금 변화는 현금 거래로 따로 입력한다.
- 원화 외 통화. 해외 종목과 차트 같은 확장 기능은 docs/05_작업지시서.md 9절의 계획이며 구현하지 않았다.

계산 공식(이동평균법 평균단가, 수수료 처리, 리밸런싱 금액, 반올림)은 docs/03_계산규칙.md 를 본다.

## 3. 사용법

화면은 위에서부터 거래 입력, 보유 현황, 자산 비중, 리밸런싱(목표 비중, 리밸런싱 결과), 거래 내역, 데이터 관리 순서로 한 페이지에 있다. 별도의 계산 버튼은 없다. 거래, 현재가, 목표 비중을 바꾸면 모든 표가 바로 다시 계산되고 자동 저장된다.

화면 메시지는 각 영역 안에 "오류: " 또는 "안내: " 로 시작하는 한 줄로 나온다. 오류가 나면 그 변경은 저장되지 않는다. 메시지 전체 목록은 docs/01_요구사항.md 5절에 있다.

### 3.1 거래 입력

1. "거래 입력" 영역에서 날짜를 고른다. 처음에는 오늘 날짜가 들어 있다. 과거 날짜도 입력할 수 있고, 계산은 날짜 순서로 다시 한다.
2. 종목명을 입력한다(예: 삼성전자). 앞뒤 공백은 지워진다. 앞뒤 공백을 지운 글자가 완전히 같아야 같은 종목이다(대소문자나 중간 공백이 다르면 다른 종목).
3. 자산군에서 "선택하세요" 대신 주식, 채권, 현금, 기타 중 하나를 고른다. 같은 종목은 하나의 자산군만 가질 수 있다.
4. 구분에서 매수 또는 매도를 고른다. 처음 값은 매수다.
5. 수량(1 이상의 정수), 가격(원), 수수료(원)를 입력한다. 수수료 칸은 비워 두면 0 으로 저장된다(칸 아래 "없으면 0").
6. "거래 추가" 버튼을 누른다(입력칸에서 Enter 를 눌러도 된다).

추가되면 종목명, 수량, 가격, 수수료 칸이 비워지고 날짜, 자산군, 구분은 그대로 남아 같은 날 거래를 이어서 입력할 수 있다. 입력이 잘못되면 버튼 아래에 "오류: " 로 시작하는 메시지가 나오고 거래를 추가하지 않으며 입력한 값은 지우지 않는다. 그 시점 보유수량보다 많이 매도하는 거래도 추가되지 않는다.

### 3.2 현금 입력

현금은 종목 하나("현금")로 기록한다.

| 항목 | 입력 값 |
|---|---|
| 종목명 | 현금 |
| 자산군 | 현금 |
| 구분 | 입금은 매수, 출금은 매도 |
| 수량 | 금액(원). 예: 100만 원 입금은 1000000 |
| 가격 | 1 |

종목명이 "현금" 인데 자산군이 현금이 아니거나 가격이 1 이 아니면 추가되지 않는다. 보유 현황에서 현금의 현재가는 1 로 고정되어 입력칸이 없다. 주식을 사고팔아도 현금 보유수량은 바뀌지 않으므로, 계좌의 현금 변화를 반영하려면 현금 거래를 따로 입력한다. 현금 거래의 수수료와 자산군 현금에 "현금" 외 종목명(예: MMF)을 쓰는 경우의 규칙은 docs/03_계산규칙.md 12절을 본다.

### 3.3 현재가 입력과 보유 현황 읽기

1. "보유 현황" 표의 현재가(원) 열에 있는 입력칸에 종목의 현재가를 입력한다. 시세는 증권사 앱 등에서 확인해 직접 넣는다.
2. Tab 으로 입력칸을 벗어나거나 Enter 를 누르면 반영되고 저장된다. Tab 을 누르면 다음 종목의 현재가 입력칸으로 이동한다.
3. 입력칸을 비우고 벗어나면 저장된 현재가가 지워지고 칸 아래에 "현재가 미입력" 이 표시된다. 현재가 미입력 종목은 평균단가로 평가한다(docs/03_계산규칙.md 7절).

표 읽는 법:

- 평가손익, 수익률, 실현손익은 수익이면 + 부호와 빨간색, 손실이면 - 부호와 파란색이다.
- 수익률(%) 처럼 열 머리에 "(%)" 가 있는 칸은 숫자에 % 를 붙이지 않는다.
- 모두 매도해 보유수량이 0 이 된 종목도 표에 남아 실현손익을 보여준다. 이때 현재가, 평가금액, 평가손익, 수익률 칸은 "-" 다.

### 3.4 자산 비중

"자산 비중" 표는 주식, 채권, 현금, 기타 4개 자산군의 평가금액과 비중(%), 합계 행의 총평가금액을 보여준다. 입력할 것은 없다. 현재가 미입력 종목도 평균단가로 평가해 포함된다. 표시된 비중은 반올림 때문에 합이 100.00 이 아닐 수 있다. 보유 중인 종목이 없으면 "안내: 보유 중인 종목이 없어 자산 비중을 계산할 수 없습니다." 가 나온다.

### 3.5 목표 비중과 리밸런싱 결과

1. "리밸런싱" 영역의 "목표 비중" 에서 주식 목표 비중(%), 채권 목표 비중(%), 현금 목표 비중(%), 기타 목표 비중(%) 칸에 원하는 비중을 입력한다. 0 이상 100 이하, 소수 첫째 자리까지 입력할 수 있다. 처음에는 네 칸 모두 0 이다.
2. 입력할 때마다 저장되고 "목표 비중 합계" 가 바로 바뀐다.
3. 합계가 100.0% 가 되면 "리밸런싱 결과" 표가 나온다. 합계가 100% 가 아니면 표 대신 "안내: 목표 비중 합계가 {합계}%입니다. 합계가 100%일 때 리밸런싱을 계산합니다." 가 나온다.

"리밸런싱 결과" 표 읽는 법:

- 열은 자산군, 현재 평가금액(원), 목표 비중(%), 목표 금액(원), 리밸런싱 금액(원), 구분이다.
- 목표 금액은 총평가금액에 목표 비중을 곱한 금액이다. 리밸런싱 금액은 목표 금액과 현재 평가금액의 차이이며 부호 없이 표시한다.
- 방향은 구분 열이 알려준다. 매수는 그 금액만큼 더 사야 하고, 매도는 그 금액만큼 팔아야 한다는 뜻이다. 표시 금액이 0 원이면 유지다.
- 주수는 계산하지 않는다. 실제 주문은 증권사 앱에서 종목과 수량을 정해 한다. 공식과 판정은 docs/03_계산규칙.md 11절을 본다.
- 보유 중인 종목이 없으면 "안내: 보유 중인 종목이 없어 리밸런싱을 계산할 수 없습니다." 가 나온다.

### 3.6 거래 삭제

1. "거래 내역" 표에서 지울 거래 행의 "삭제" 버튼을 누른다. 거래 내역은 날짜가 오래된 거래가 위에 있다.
2. 확인 창에 "{날짜} {종목명} {구분} {수량} 거래를 삭제하시겠습니까?" 가 나온다. 확인을 누르면 삭제되고, 취소를 누르면 아무것도 바뀌지 않는다.

되돌리기 기능은 없다. 삭제하면 이후 매도가 보유수량을 넘게 되는 거래(예: 매도가 남아 있는 종목의 매수 거래)는 삭제되지 않고 오류 메시지가 나온다. 이때는 뒤의 매도 거래부터 지운다. 거래 수정 기능은 없으므로 잘못 입력한 거래는 삭제한 뒤 다시 입력한다.

### 3.7 JSON 내보내기와 불러오기

내보내기:

1. "데이터 관리" 영역에서 "JSON 내보내기" 버튼을 누른다.
2. `portfolio-tracker-YYYY-MM-DD.json`(내보낸 날짜) 파일이 내려받아진다. 거래, 현재가, 목표 비중이 모두 들어 있다. 파일은 브라우저 안에서 만들어지며 서버로 보내지 않는다.

불러오기:

1. "JSON 불러오기" 버튼을 누르고 내보냈던 JSON 파일을 고른다.
2. 파일 형식이 맞으면 확인 창에 "현재 데이터(거래 {현재 건수}건)를 불러온 파일의 데이터(거래 {파일 건수}건)로 모두 교체합니다. 계속하시겠습니까?" 가 나온다.
3. 확인을 누르면 현재 데이터 전체가 파일 내용으로 바뀌고 "안내: 불러오기를 완료했습니다." 가 나온다. 취소하면 아무것도 바뀌지 않는다.

불러오기는 합치기가 아니라 전체 교체다. 파일을 읽을 수 없거나 형식이 틀리면 "오류: " 로 시작하는 메시지가 나오고 기존 데이터는 바뀌지 않는다. 검사 항목은 docs/01_요구사항.md 4.13 과 docs/02_설계문서.md 5.7 을 본다.

## 4. 데이터 보존과 백업

데이터는 지금 쓰는 브라우저의 localStorage(키 `portfolio-tracker:v1`)에만 저장되고 외부로 전송되지 않는다. 그래서 다음 경우에는 데이터가 보이지 않거나 사라진다(상세는 docs/01_요구사항.md 6.1).

- 다른 브라우저나 다른 기기에서 열 때
- 브라우저의 사이트 데이터를 지우거나 시크릿(사생활 보호) 창을 닫을 때
- Safari 에서 일정 기간(7일) 사이트를 쓰지 않았을 때

거래를 입력한 뒤에는 "JSON 내보내기" 로 주기적으로 백업한다. 앱은 백업을 강제하지 않는다. 다른 기기로 옮길 때도 내보낸 파일을 그 기기에서 "JSON 불러오기" 로 연다. 저장에 실패하거나 저장된 데이터를 읽지 못하면 "데이터 관리" 영역에 오류 메시지가 나온다. 저장된 데이터를 읽지 못한 경우 빈 상태로 시작하므로 백업 파일을 불러와 복구한다.

## 5. 로컬에서 열어 보기

앱은 서버 기능 없이 동작한다. 다만 ES 모듈은 `file://` 주소(파일을 두 번 눌러 여는 방식)로 열리지 않으므로, 로컬에서 열어 볼 때는 확인 용도로만 정적 파일 서버를 띄운다(docs/01_요구사항.md 6.2).

1. 이 저장소 루트(index.html 이 있는 폴더)에서 서버를 띄운다.

   ```
   py -m http.server 8000
   ```

   `py` 는 Windows 의 Python 런처다. 다른 환경에서는 `python3 -m http.server 8000` 을 쓴다.

2. 브라우저에서 `http://localhost:8000/` 을 연다. 거래 id 를 만드는 crypto.randomUUID 가 보안 컨텍스트에서만 동작하므로 `http://localhost` 나 `http://127.0.0.1` 로 연다. 같은 네트워크의 다른 IP 주소로 열면 동작하지 않을 수 있다.
3. 확인이 끝나면 서버를 띄운 창에서 Ctrl+C 로 끈다.

localhost 에 저장한 데이터는 배포 주소의 데이터와 출처가 달라 서로 보이지 않는다.

## 6. 배포

GitHub Pages 정적 호스팅으로 배포한다. 빌드 단계, 서버 코드, package.json 이 없으므로 저장소의 파일이 그대로 게시된다(docs/01_요구사항.md 6절 NFR-01).

준비물은 GitHub 계정과 git 이다. 저장소를 명령으로 만들려면 GitHub CLI(`gh`)를 설치하고 `gh auth login` 으로 로그인해 둔다.

### 6.1 배포 절차

1. GitHub 에 저장소를 만든다. 무료 계정은 공개(Public) 저장소에서 Pages 를 쓸 수 있다. 아래 두 방법 중 하나를 쓴다.
   - 웹 화면: github.com 에 로그인하고 오른쪽 위 "+" -> "New repository" 를 누른다. Repository name 에 저장소 이름(예: portfolio-tracker)을 넣고 Public 을 고른다. 로컬 저장소에 이미 커밋이 있으므로 README, .gitignore, license 는 추가하지 않는다(추가하면 원격에 다른 커밋이 생겨 첫 push 가 거부된다). "Create repository" 를 누른 뒤 2번으로 간다.
   - gh CLI: 저장소 루트에서 아래 명령을 실행한다. 저장소 생성, 원격 origin 추가, 현재 브랜치 push 를 한 번에 하므로 2번을 건너뛰고 3번으로 간다.

     ```
     gh repo create {저장소 이름} --public --source=. --remote=origin --push
     ```

2. 로컬 저장소에 원격을 추가하고 main 브랜치를 push 한다. 현재 브랜치가 main 인지 `git branch --show-current` 로 먼저 확인한다.

   ```
   git remote add origin https://github.com/{사용자 이름}/{저장소 이름}.git
   git push -u origin main
   ```

3. GitHub 의 저장소 페이지에서 Settings -> Pages 를 연다. Build and deployment 에서 Source 를 "Deploy from a branch" 로, Branch 를 "main" 으로, 폴더를 "/ (root)" 로 고르고 Save 를 누른다.
4. 게시를 기다린다. 저장소 Actions 탭의 "pages build and deployment" 실행이 끝나면(보통 몇 분) Settings -> Pages 위쪽에 게시 주소가 나온다.
5. `https://{사용자 이름}.github.io/{저장소 이름}/` 을 연다. 실행이 끝나기 전에는 404 가 나올 수 있으므로 몇 분 뒤 다시 연다.
6. 6.4 의 확인을 한다.

이후 main 브랜치에 push 할 때마다 같은 방식으로 다시 게시된다. 반영에도 몇 분이 걸리며, 이전 화면이 보이면 Ctrl+F5 로 새로 불러온다. 저장소 이름을 `{사용자 이름}.github.io` 로 만들면 하위 경로 없는 사용자 사이트가 되는데, 이 README 는 하위 경로가 붙는 프로젝트 페이지를 기준으로 한다.

### 6.2 하위 경로와 저장 데이터

- 모든 파일 경로가 상대 경로이므로(docs/02_설계문서.md 1.1) `/{저장소 이름}/` 하위 경로에서 그대로 동작한다.
- 같은 사용자 주소(`{사용자 이름}.github.io`) 아래 다른 프로젝트 페이지와 localStorage 출처를 공유한다(docs/01_요구사항.md 6.1 4번). 저장 키에 `portfolio-tracker:` 접두어를 써서 구분하지만, 브라우저에서 이 출처의 사이트 데이터를 지우면 다른 프로젝트 페이지의 데이터와 함께 지워진다. JSON 내보내기로 백업한다(4절).
- 배포 주소의 데이터와 localhost 의 데이터는 출처가 달라 서로 보이지 않는다. 옮기려면 JSON 내보내기와 불러오기를 쓴다.

### 6.3 Jekyll 과 .nojekyll

"Deploy from a branch" 는 게시 전에 저장소를 Jekyll 로 처리한다. Jekyll 은 밑줄(_)로 시작하는 파일과 폴더를 게시하지 않고, Markdown 파일과 YAML 머리(`---`)가 있는 파일을 변환한다. 이 저장소에는 밑줄로 시작하는 파일과 폴더가 없고 앱 파일(index.html, css/style.css, js/*.js)에는 YAML 머리가 없어 그대로 게시되므로 `.nojekyll` 없이 배포한다.

Actions 탭의 "pages build and deployment" 가 Jekyll 처리 단계에서 실패하면 저장소 루트에 빈 `.nojekyll` 파일을 추가해 Jekyll 처리를 끄는 방법이 있다. 이 파일은 정해진 파일구조(AGENTS.md 4절) 밖이므로 작업자는 실제로 추가하기 전에 사용자 승인을 받는다(docs/05_작업지시서.md T5-02).

### 6.4 배포 후 확인

게시 주소에서 직접 확인한다.

1. 화면 하단에 고지 문구 "계산 결과는 참고용이며 투자 판단의 책임은 본인에게 있습니다." 가 보인다.
2. 거래 1건(예: 3.2 의 현금 입금. 종목명 현금, 자산군 현금, 매수, 수량 1000000, 가격 1)을 추가하고 새로고침한다. 거래 내역과 보유 현황에 그대로 남아 있으면 저장이 동작한다. 확인한 뒤 그 거래를 "삭제" 로 지운다.
3. 브라우저 개발자 도구(F12)의 Network 탭을 열고 새로고침한다. 모든 요청이 `{사용자 이름}.github.io` 로만 가야 한다(외부 요청 0 건, docs/01_요구사항.md 6절 NFR-07). Console 탭에 오류가 없어야 한다.

화면 검증 스크립트로도 확인한다. 준비 명령은 docs/05_작업지시서.md 2.3 을 본다.

```
py skills/ui-verify/scripts/verify_ui.py T4-07 T4-13 T4-14 T4-15 --base-url https://{사용자 이름}.github.io/{저장소 이름}/
```

`--base-url` 을 주면 로컬 서버를 띄우지 않고 그 주소를 검사한다. 외부 요청 판정의 허용 출처는 그 주소의 출처이고, 모든 시나리오가 통과하면 종료 코드가 0 이다(skills/ui-verify/SKILL.md). 스크립트는 새 브라우저 환경에서 실행되므로 평소 쓰는 브라우저의 데이터는 바뀌지 않는다. 지원 브라우저 범위는 docs/01_요구사항.md 6절 NFR-02 를 본다.
